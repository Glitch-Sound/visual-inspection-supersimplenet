## 背景と現行業務フロー

1. 運用者は型番別設定と基準画像を用意し、縮小後の画像を基準に `range` の座標を設定する。
2. `check` で範囲を確認し、`train-pre` と `test-pre` で元画像を準備する。実行中は処理件数と進行状況を把握しにくい。
3. `train` が正常画像のスコアから暫定閾値を計算し、型番設定、checkpoint、最良試行結果へ同じ値を保存する。
4. `test` は暫定閾値で判定し、元画像単位の結果を保存する。各 CLI は終了時に実行記録を JSON で表示する。

## 利用者と運用者

| 役割 | 利用場面 | 目的・必要な判断 |
| --- | --- | --- |
| 運用者 | 設定、画像準備、学習、検査 | 原画像上の対象位置を指定し、処理状況と失敗理由を把握する |
| 評価者 | 閾値の調整と検査結果の確認 | 学習由来の暫定閾値と実際の判定閾値を区別し、検査結果を評価する |

## 解決する課題

暫定閾値を維持したまま検査時の判定境界を調整できない。<br />
CLI の終了時 JSON だけでは処理段階が分かりにくく、画像準備中の進捗が見えない。<br />
`range` が縮小後座標のため、元画像で確認した位置を設定へそのまま記入できない。

## 変更後の業務フロー

1. 運用者は元画像の左上を原点とした `range` 座標を設定する。`check` でその位置と切り出し対象を確認する。
2. `train-pre` と `test-pre` は元画像座標を共通縮小倍率で換算し、縮小・位置合わせ後の画像から `SIZE` ピクセル四方を切り出す。運用者は各コマンドの進行状況と結果を確認する。
3. `train` は従来どおり暫定閾値を生成する。評価者は必要な場合だけ、Optuna の学習設定から独立した検査用閾値を型番設定で指定する。
4. `test` は検査用閾値が未指定または `null` なら暫定閾値を、0から1の数値なら指定値を用いて判定し、使用した閾値を結果に記録する。
5. 設定不備や範囲外は理由を表示して中止する。位置合わせ失敗の除外・未判定は維持し、修正後に準備または検査を再実行する。

## 対象範囲

### 対象

- 型番別の検査用閾値と暫定閾値の優先規則、判定結果への使用値の記録。
- 5 CLI の人が読める実行表示と、`train-pre`・`test-pre` の進捗表示。
- `range` の縮小前座標への変更と、確認画像・学習準備・試験準備の整合。
- 既存設定と成果物を使う際の再確認・再生成手順。

### 対象外

- 暫定閾値の算出方法、Optuna の探索条件、特徴抽出器の変更。別の責務として扱う。
- 検査用閾値の自動最適化。本変更では評価者が値を指定する。

## 運用開始の受け入れ条件

- AC-001: 検査用閾値が未指定または `null` のとき暫定閾値で判定し、0と1を含む有効な指定値では指定値で判定する。学習由来の暫定閾値と成果物の整合は維持する。
- AC-002: 検査用閾値が範囲外または数値でないとき、対象項目と理由を示して検査前に拒否する。結果には判定に使用した閾値を記録する。
- AC-003: 各 CLI で開始、進行または処理段階、終了結果、警告・エラーが理解でき、既存の機械可読な終了記録と終了コードを利用できる。`train-pre` と `test-pre` では対象元画像の処理件数と進捗が分かる。
- AC-004: `range` の座標を縮小前画像で指定できる。例えば `RESIZE = 0.5`、`x = 400` は縮小後の `x = 200` に対応し、切り出した分割画像は `SIZE` ピクセル四方となる。`check` と両準備コマンドの対象位置が一致する。
- AC-005: 不正な座標・縮小倍率・範囲外を理由付きで拒否し、画像準備の途中失敗時には既存の準備成果物を保全する。位置合わせ失敗時には学習対象からの除外または試験の未判定引き継ぎを維持する。
- AC-006: 既存の `range` 値を縮小前座標へ移す方法と、換算後の切り出し位置・画像内容が旧成果物と同じかを確認する手順が示される。位置や画像内容が変わる場合には、学習・試験準備画像、モデル、検査結果を再生成する手順が示される。

## 変更する能力

### 新規能力

なし。

### 変更する既存能力

- `visual-inspection/image-preparation`: 縮小前座標による範囲確認と画像準備、準備コマンドの進捗。
- `visual-inspection/model-evaluation`: 検査用閾値の優先規則、使用値の結果記録、検査 CLI の表示。

## 影響範囲

- **利用者・業務**: 評価者は検査用閾値の出所を確認し、運用者は座標と処理進捗を確認する。
- **API・外部連携**: CLI の名称と引数は維持する。標準出力の機械可読 JSON 契約と終了コードを維持する。
- **データ**: **BREAKING** `range` の座標系が変わる。既存の型番別座標は見直しが必要で、切り出し位置または画像内容が変わる型番では準備画像、モデル、結果を再生成する。
- **品質・運用**: 縮小時の丸めと境界の扱い、進捗表示とログ収集の両立、対象 OS の表示を検証する。`model-training` の暫定閾値生成契約は維持し、学習 CLI の表示は `model-evaluation` に置く横断要件で扱う。
