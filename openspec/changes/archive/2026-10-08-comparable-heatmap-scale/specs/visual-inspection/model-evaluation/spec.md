## ADDED Requirements

### Requirement: REQ-019 型番別ヒートマップ表示範囲の指定

システムは、運用者が型番の検査を実行する時に、型番別設定に明示したヒートマップ表示範囲の下限と上限を検査画像間で共通して使用しなければならない (MUST)。

下限と上限は有限の数値で、下限は上限より小さくなければならない。異常マップの値域を異常スコアの `0`〜`1` に限定しない。表示範囲は異常スコア、暫定閾値、検査用閾値と独立する。

#### Scenario: REQ-019-S01 有効な表示範囲を使用する

- **GIVEN** 型番別設定に有限の数値で下限が上限より小さい表示範囲がある
- **WHEN** 運用者がその型番の検査を実行する
- **THEN** システムは同じ表示範囲をその検査の全分割画像の可視化に使用する
- **AND** 異常スコアと判定閾値を表示範囲から変更しない

#### Scenario: REQ-019-S02 未指定または不正な表示範囲を拒否する

- **GIVEN** 型番別設定の表示範囲が未指定、片側だけ指定、数値以外、真偽値、非有限値、または下限が上限以上である
- **WHEN** 運用者がその型番の検査を実行する
- **THEN** システムは不正な項目と理由を示して推論前に入力不備として拒否する
- **AND** 不完全な検査結果を正常な結果として保存しない
- **AND** 運用者は表示範囲を修正して再実行できる

## MODIFIED Requirements

### Requirement: REQ-010 分割画像のスコア・判定・可視化

システムは、運用者が型番の検査を要求した時に、型番別の単一学習済みパラメータを全分割 ID へ適用し、分割画像ごとの異常スコア、型番別閾値との比較結果および結果画像を保存しなければならない(MUST)。

試験時は閾値算出時と同じ決定的前処理を使用し、AnomalibのPostProcessorを無効にしたSuperSimpleNetの`pred_score`を異常スコアとし、`pred_score >= threshold`を`anomaly`、それ以外を`normal`と判定しなければならない(MUST)。ヒートマップには同じ推論で得たPostProcessor適用前の`anomaly_map`を分割画像サイズへリサイズして使用しなければならない(MUST)。異常と判定した分割画像のヒートマップは型番別設定の表示範囲で色付けし、下限未満の値は下限の色、上限を超える値は上限の色に固定しなければならない(MUST)。同じ表示範囲では同じ異常マップ値に同じヒートマップ色を割り当て、画像ごとの最小値・最大値で色付けを変更してはならない(MUST NOT)。

#### Scenario: REQ-010-S01 正常な分割画像を記録する

- **GIVEN** スコア契約が一致する型番の学習済みパラメータと閾値があり、分割画像の`pred_score`が閾値未満である
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** システムは分割画像のスコアと `normal` 判定を保存する
- **AND** データ拡張を適用せず、入力内容を変更していない結果画像を保存する

#### Scenario: REQ-010-S02 異常な分割画像を可視化する

- **GIVEN** スコア契約が一致する型番の学習済みパラメータと閾値があり、分割画像の`pred_score`が閾値以上である
- **WHEN** 運用者が検査を実行する
- **THEN** システムは分割画像のスコアと `anomaly` 判定を保存する
- **AND** 型番別設定の共通表示範囲で異常箇所を色付けしたヒートマップを重ねた結果画像を保存する

#### Scenario: REQ-010-S03 閾値算出と同じ前処理を使用する

- **GIVEN** bilinear補間、antialiasおよびImageNet正規化を設定したSuperSimpleNetがある
- **WHEN** システムが探索、暫定閾値算出または試験推論の入力を生成する
- **THEN** システムはモデルに設定した同一の決定的前処理を使用する
- **AND** 別ライブラリによる近似前処理を併用しない

#### Scenario: REQ-010-S04 画像間で色を比較する

- **GIVEN** 同じ学習済みモデルと表示範囲で検査され、異なる最小値・最大値を持つ二つの異常マップがある
- **WHEN** 運用者が検査を実行する
- **THEN** 両結果のヒートマップ層では同じ異常マップ値が同じ色になり、範囲外の値はそれぞれ端の色になる
- **AND** 画像全体のスコアと判定は表示範囲によって変わらない

### Requirement: REQ-012 元画像単位の検査結果契約

システムは、検査対象の元画像ごとに、元画像名、型番、使用した学習済みパラメータ、スコア契約、閾値、使用したヒートマップ表示範囲、各分割 ID・画像名・異常スコア・判定・結果画像・エラー、元画像判定、処理日時、位置合わせ結果、エラー、警告および共通実行記録を機械可読な結果として保存しなければならない(MUST)。
スコア契約のスコア源は`supersimplenet.pred_score`、PostProcessorの有効状態は`false`に限定しなければならない(MUST)。共通実行記録にはコマンド、型番、開始・終了日時、コマンド単位の処理時間、終了コード、終了状態、デバイス、OS・Python、主要依存関係、警告およびエラーを含めなければならない(MUST)。

#### Scenario: REQ-012-S01 追跡可能な JSON 結果を保存する

- **GIVEN** 型番の検査入力が有効で、対象元画像について正常、異常、未判定、または一部分割の推論エラーを含む判定を確定できる
- **WHEN** システムが元画像の検査結果を確定する
- **THEN** システムは必須項目と、使用したヒートマップ表示範囲、各分割の `normal`、`anomaly`、`undetermined`、`error` のいずれかの判定、および `REQ-011` に従う元画像判定を含む JSON を元画像単位で保存する
- **AND** 判定不能な分割の異常スコアを `null` として保存する

#### Scenario: REQ-012-S02 不正な結果契約を拒否する

- **GIVEN** スコア源が`supersimplenet.pred_score`ではない、PostProcessorが有効、ヒートマップ表示範囲が欠落または不正、分割または元画像の判定が列挙値外、共通実行記録の必須項目が欠落、または日時にタイムゾーンがない結果データがある
- **WHEN** システムが元画像単位の検査結果を生成または読み戻す
- **THEN** システムは不正な項目と理由を示して結果契約を拒否する
- **AND** 不正なデータを正常な検査結果として扱わない

#### Scenario: REQ-012-S03 同じstemの元画像結果を区別して保存する

- **GIVEN** 同じstemで拡張子だけが異なる複数の試験元画像がある
- **WHEN** システムが検査結果を保存する
- **THEN** システムは拡張子付き元画像名を含む一意なJSON名と、拡張子付き分割画像名を含む一意な結果画像名を使用する
- **AND** 一方の元画像または分割結果で他方を上書きしない

#### Scenario: REQ-012-S04 不正な試験manifestのパスと対応関係を拒否する

- **GIVEN** 試験manifestの型番が要求型番と異なる、元画像名・分割画像名にパス要素がある、元画像・分割画像が重複する、または分割の元画像参照・IDが不整合である
- **WHEN** 運用者が検査を実行する
- **THEN** システムは不正な項目と理由を示して推論前に拒否する
- **AND** 準備領域および結果ステージング領域外のファイルを読み書きしない

## 試験方針

| 要件区分 | 試験層 | 試験パターン | 自動化方針・利用者が確認する結果 |
| --- | --- | --- | --- |
| 表示範囲設定 | unit / integration | 有効、未指定、片側欠落、非数値、真偽値、非有限値、同値・逆順 | 各 Scenario を自動検証し、推論前の拒否理由と結果未保存を確認する |
| 推論・可視化 | unit / integration | 正常画像保持、異常画像の共通尺度、範囲外固定、スコア・判定不変、既存前処理 | 各 Scenario を自動検証し、固定画像と異常マップで結果画素・判定を確認する |
| 結果契約 | unit / integration | 使用範囲の記録と読戻し、範囲欠落・不正、既存の結果契約 | 各 Scenario を自動検証し、保存 JSON の値と不正データ拒否を確認する |

正常画像にヒートマップを重ねない。位置合わせ失敗や未判定の集約は従来どおりで、可視化対象を増やさない。権限制御と外部通知は本能力に存在せず、この変更では扱わない。
