## 背景と現行業務フロー

1. 運用者は型番別設定、学習済みモデル、検査用画像を用意して検査する。
2. システムは分割画像ごとの異常スコアを閾値と比較し、異常な画像にヒートマップを重ねる。
3. 評価者は保存された結果画像と JSON を確認する。現在のヒートマップは画像ごとの異常マップの最小値・最大値で色を割り当てるため、画像間で同じ色が同じ値を示すとは限らない。

## 利用者と運用者

| 役割 | 利用場面 | 目的・必要な判断 |
| --- | --- | --- |
| 運用者 | 型番別設定と検査を扱う時 | 学習済みモデルに適した表示範囲を設定し、設定不備を修正して再実行する |
| 評価者 | 検査結果を確認する時 | 同じ学習済みモデルと表示範囲で生成したヒートマップの色を比較し、異常箇所を確認する |

## 解決する課題

画像ごとの色割り当てでは、同じ学習済みモデルによる結果でも同じ赤が異なる異常マップ値を示す。
評価者が色の強さを画像間で比較できず、異常箇所の確認を誤るおそれがある。

## 変更後の業務フロー

1. 運用者は型番別設定に、ヒートマップの下限と上限を明示する。学習済みモデルを更新した場合は、そのモデルに適した表示範囲を確認する。
2. システムは表示範囲を検査前に検証し、設定がない、または無効なら理由を示して検査を開始しない。運用者は設定を修正して再実行する。
3. システムは従来どおり異常スコアと判定閾値で分割画像を判定する。異常と判定した画像だけ、型番別の共通表示範囲で異常マップを色付けする。範囲外の値は端の色に固定する。正常画像は元の内容のまま保存する。
4. システムは使用した表示範囲を結果 JSON に記録する。運用者は比較対象に同じ学習済みモデルを使用したことを運用で確認し、評価者は同じ表示範囲の結果を比較する。
5. 表示範囲の変更後に結果を更新する場合は、運用者が既存の再検査手順を実行する。`test --restart` は旧結果を先に削除するため、必要な旧結果は実行前に退避する。

## 対象範囲

### 対象

- 型番別のヒートマップ表示範囲の指定、検証、色付け、結果への記録。
- 異常判定時だけのヒートマップ適用、および異常スコア・判定閾値・判定結果の維持。
- 設定方法と比較条件の案内。

### 対象外

- 学習、異常スコア、判定閾値の算出方法の変更。可視化と判定は独立しているため。
- 既存の結果画像・JSON の移行や再生成。利用者は本仕様適用後に検査をやり直すため。
- 表示範囲の自動算出。運用者が型番別に指定するため。
- 学習済みモデルの同一性を結果 JSON で自動証明すること。比較対象のモデル確認は運用で行うため。

## 運用開始の受け入れ条件

- AC-001: 同じ学習済みモデルと表示範囲で検査した異常画像では、ヒートマップ層の同じ異常マップ値が同じ色に対応し、範囲外の値は端の色になる。元画像と重ねた最終画素の色は元画像によって異なってよい。
- AC-002: ヒートマップは異常と判定した分割画像だけに適用され、正常画像の保存内容、異常スコア、判定閾値、判定結果は表示範囲の変更によって変わらない。
- AC-003: 検査結果 JSON に使用した表示範囲が記録され、設定を変更して再検査した結果と区別できる。
- AC-004: 表示範囲の未指定または不正な設定は検査前に理由付きで拒否され、運用者が修正して再実行できる。

## 変更する能力

### 新規能力

なし。

### 変更する既存能力

- `visual-inspection/model-evaluation`: 異常画像のヒートマップを型番別の共通表示範囲で描画し、範囲と検証結果を記録する。

## 影響範囲

- **利用者・業務**: 運用者は型番別表示範囲を指定し、モデル更新時に見直す。比較対象に同じ学習済みモデルを使用したことを運用で確認する。評価者は同じモデルと表示範囲の結果を比較する。
- **API・外部連携**: CLI の検査入力条件と機械可読な結果 JSON が変わる。外部連携の追加はない。
- **データ**: **BREAKING** 型番別設定に表示範囲が必須となる。既存設定は追記が必要。既存結果は移行せず、新しい結果は再検査で生成する。
- **品質・運用**: 表示範囲の妥当性と色の一貫性を自動検証する。対象 OS での画像表示確認は自動試験と区別する。
