# モデル評価の差分仕様

## ADDED Requirements

### Requirement: REQ-023 検査対象グループの選択と事前照合

システムは、運用者が `test --model <型番>` を実行した時に全グループを、`--group <ID>` を指定した時にそのグループだけを検査し、対象グループの学習成果物を推論前に照合しなければならない(MUST)。

#### Scenario: REQ-023-S01 全グループを検査する

- **GIVEN** 全グループの整合した学習成果物と全分割の試験準備結果がある
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** 元画像ごとに全グループの検査結果が保存される

#### Scenario: REQ-023-S02 指定グループだけを検査する

- **GIVEN** 指定グループの学習成果物と全分割の試験準備結果があり、他グループの結果も存在する
- **WHEN** 運用者が `test --model <型番> --group <ID>` を実行する
- **THEN** 指定グループの結果だけが更新され、他グループの結果は保持される

#### Scenario: REQ-023-S03 不足モデルを検査前に通知する

- **GIVEN** 対象グループの一つ以上でcheckpointまたは最良試行結果が欠けている
- **WHEN** 運用者が検査を実行する
- **THEN** 不足するグループIDと成果物を示して入力不備として終了する
- **AND** 推論を開始せず既存結果を更新しない

#### Scenario: REQ-023-S04 未定義グループを拒否する

- **GIVEN** 設定に存在しないグループIDが指定される
- **WHEN** 運用者が検査を実行する
- **THEN** 利用可能なグループIDを示して入力不備として終了し、既存結果を保持する

#### Scenario: REQ-023-S05 全グループの検査途中失敗で結果を保持する

- **GIVEN** 複数グループの既存検査結果があり、全グループの検査中に後続グループで処理全体の失敗が起こる
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** コマンドは失敗グループIDと理由を示してエラー終了する
- **AND** 今回生成した結果を公開せず、実行前の全グループの結果一式を保持する

## MODIFIED Requirements

### Requirement: REQ-010 分割画像のスコア・判定・可視化

システムは、運用者が型番の検査を要求した時に、対象グループの学習済みパラメータをそのグループの全分割 ID へ適用し、分割画像ごとの異常スコア、対象グループの閾値との比較結果および結果画像を保存しなければならない(MUST)。

試験時は閾値算出時と同じ決定的前処理を使用し、AnomalibのPostProcessorを無効にしたSuperSimpleNetの`pred_score`を異常スコアとし、`pred_score >= threshold`を`anomaly`、それ以外を`normal`と判定しなければならない(MUST)。ヒートマップには同じ推論で得たPostProcessor適用前の`anomaly_map`を分割画像サイズへリサイズして使用しなければならない(MUST)。異常と判定した分割画像のヒートマップは対象グループの表示範囲で色付けし、下限未満の値は下限の色、上限を超える値は上限の色に固定しなければならない(MUST)。同じ表示範囲では同じ異常マップ値に同じヒートマップ色を割り当て、画像ごとの最小値・最大値で色付けを変更してはならない(MUST NOT)。

#### Scenario: REQ-010-S01 正常な分割画像を記録する

- **GIVEN** スコア契約が一致する型番の学習済みパラメータと閾値があり、分割画像の`pred_score`が閾値未満である
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** システムは分割画像のスコアと `normal` 判定を保存する
- **AND** データ拡張を適用せず、入力内容を変更していない結果画像を保存する

#### Scenario: REQ-010-S02 異常な分割画像を可視化する

- **GIVEN** スコア契約が一致する型番の学習済みパラメータと閾値があり、分割画像の`pred_score`が閾値以上である
- **WHEN** 運用者が検査を実行する
- **THEN** システムは分割画像のスコアと `anomaly` 判定を保存する
- **AND** 元の分割画像を左、対象グループの共通表示範囲で色付けしたヒートマップを同じ画像に重ねた画像を右に、同じ高さで横に並べた結果画像を保存する

#### Scenario: REQ-010-S03 閾値算出と同じ前処理を使用する

- **GIVEN** bilinear補間、antialiasおよびImageNet正規化を設定したSuperSimpleNetがある
- **WHEN** システムが探索、暫定閾値算出または試験推論の入力を生成する
- **THEN** システムはモデルに設定した同一の決定的前処理を使用する
- **AND** 別ライブラリによる近似前処理を併用しない

#### Scenario: REQ-010-S04 画像間で色を比較する

- **GIVEN** 同じ学習済みモデルと表示範囲で検査され、異なる最小値・最大値を持つ二つの異常マップがある
- **WHEN** 運用者が検査を実行する
- **THEN** 両結果のヒートマップ層では同じ異常マップ値が同じ色になり、範囲外の値はそれぞれ端の色になる
- **AND** 画像全体のスコアと判定は表示範囲によって変わらない

### Requirement: REQ-011 元画像単位の判定集約

システムは、同じ元画像・グループに属する分割判定を集約する時に、一つでも `anomaly` があればそのグループの元画像判定を `anomaly`、全分割が `normal` の場合だけそのグループの元画像判定を `normal`、それ以外はそのグループの元画像判定を `undetermined` と記録しなければならない(MUST)。

#### Scenario: REQ-011-S01 一つの異常を元画像の異常へ集約する

- **GIVEN** 同じ元画像・グループの分割判定に一つ以上の `anomaly` がある
- **WHEN** システムが元画像結果を集約する
- **THEN** システムは他の分割判定にかかわらずそのグループの元画像判定を `anomaly` と記録する

#### Scenario: REQ-011-S02 全分割正常を元画像の正常へ集約する

- **GIVEN** 同じ元画像・グループに必要な全分割が存在し、全ての分割判定が `normal` である
- **WHEN** システムが元画像結果を集約する
- **THEN** システムはそのグループの元画像判定を `normal` と記録する

#### Scenario: REQ-011-S03 判定不能を未判定へ集約する

- **GIVEN** `anomaly` はなく、位置合わせ失敗、分割不足、推論失敗その他の理由による `undetermined` または `error` の分割が一つ以上ある
- **WHEN** システムが元画像結果を集約する
- **THEN** システムはそのグループの元画像判定を `undetermined` と記録する
- **AND** 原則として再撮影が必要であり、別の扱いは評価者判断であることを結果へ記録する

#### Scenario: REQ-011-S04 グループ間の判定を集約しない

- **GIVEN** 同じ元画像を検査した二つのグループで判定が異なる
- **WHEN** 運用者が結果を確認する
- **THEN** グループごとの判定が区別して保存され、グループ間を集約した型番全体の判定は保存されない

### Requirement: REQ-012 元画像単位の検査結果契約

システムは、検査対象の元画像・グループごとに、元画像名、型番、グループID、対象分割ID、使用した学習済みパラメータ、スコア契約、閾値、使用したヒートマップ表示範囲、各分割 ID・画像名・異常スコア・判定・結果画像・エラー、グループ内の元画像判定、処理日時、位置合わせ結果、エラー、警告および共通実行記録を機械可読な結果として保存しなければならない(MUST)。
スコア契約のスコア源は`supersimplenet.pred_score`、PostProcessorの有効状態は`false`に限定しなければならない(MUST)。共通実行記録にはコマンド、型番、処理したグループID、開始・終了日時、コマンド単位の処理時間、終了コード、終了状態、デバイス、OS・Python、主要依存関係、警告およびエラーを含めなければならない(MUST)。

#### Scenario: REQ-012-S01 追跡可能な JSON 結果を保存する

- **GIVEN** 型番の検査入力が有効で、対象元画像について正常、異常、未判定、または一部分割の推論エラーを含む判定を確定できる
- **WHEN** システムが元画像の検査結果を確定する
- **THEN** システムは必須項目と、使用したヒートマップ表示範囲、各分割の `normal`、`anomaly`、`undetermined`、`error` のいずれかの判定、および `REQ-011` に従うグループ内の元画像判定を含む JSON を元画像・グループ単位で保存する
- **AND** 判定不能な分割の異常スコアを `null` として保存する

#### Scenario: REQ-012-S02 不正な結果契約を拒否する

- **GIVEN** スコア源が`supersimplenet.pred_score`ではない、PostProcessorが有効、ヒートマップ表示範囲が欠落または不正、分割または元画像の判定が列挙値外、共通実行記録の必須項目が欠落、または日時にタイムゾーンがない結果データがある
- **WHEN** システムが元画像単位の検査結果を生成または読み戻す
- **THEN** システムは不正な項目と理由を示して結果契約を拒否する
- **AND** 不正なデータを正常な検査結果として扱わない

#### Scenario: REQ-012-S03 同じstemの元画像結果を区別して保存する

- **GIVEN** 同じstemで拡張子だけが異なる複数の試験元画像がある
- **WHEN** システムが検査結果を保存する
- **THEN** システムは拡張子付き元画像名を含む一意なJSON名と、拡張子付き分割画像名を含む一意な結果画像名を使用する
- **AND** 一方の元画像または分割結果で他方を上書きしない

#### Scenario: REQ-012-S04 不正な試験manifestのパスと対応関係を拒否する

- **GIVEN** 試験manifestの型番が要求型番と異なる、元画像名・分割画像名にパス要素がある、元画像・分割画像が重複する、分割の元画像参照が不整合である、分割IDが型番設定に存在しない、分割画像名が元画像名と2桁にゼロ埋めした分割IDから決まる名前と異なる、または準備領域・manifest・参照分割画像がシンボリックリンクである
- **WHEN** 運用者が検査を実行する
- **THEN** システムは不正な項目と理由を示して推論前に拒否する
- **AND** リンク先を含む準備領域および結果ステージング領域外のファイルを読み書きせず、不正入力を理由に既存の検査結果を削除しない

#### Scenario: REQ-012-S05 グループの結果を区別する

- **GIVEN** 同じ元画像・分割IDを二つのグループで検査する
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** 各グループの結果画像とJSONが別々に保存され、互いを上書きしない
- **AND** それぞれのモデル、閾値、表示範囲を識別できる

#### Scenario: REQ-012-S06 準備時と異なる試験設定を拒否する

- **GIVEN** 試験準備後に分割位置、画像サイズまたは位置合わせ条件が変わり、manifestの準備指紋が現在の設定と一致しない
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** システムは設定と準備結果の不一致を示して推論前に入力不備として終了する
- **AND** 既存結果を保持し、`test-pre` の再実行を案内する

### Requirement: REQ-013 明示的な再検査

システムは、通常の `test` の再実行で対象範囲の結果を再生成し、完成した不変の結果世代を型番ごとの参照ファイル `current.json` の原子的なファイル置換で公開しなければならない(MUST)。全グループの実行では全グループの参照を一度に切り替え、指定グループの実行ではそのグループの参照だけを切り替えなければならない(MUST)。参照ファイルの切替前に旧結果世代を削除してはならない(MUST NOT)。公開後は各グループの現行参照が示す結果だけを残し、参照されない結果を安全に整理しなければならない(MUST)。`test` は `--restart` を受け付けない。

#### Scenario: REQ-013-S01 旧結果だけを置き換える

- **GIVEN** 全グループの旧検査結果が存在する
- **WHEN** 運用者が `test --model <型番>` を再実行する
- **THEN** 全グループの新結果一式が完成した後、参照ファイルが一度の置換で新世代を示す
- **AND** 元画像、型番設定、事前学習重み、学習済みパラメータおよび試験準備済み画像を削除しない

#### Scenario: REQ-013-S02 指定グループだけを再検査する

- **GIVEN** 複数グループの検査結果がある
- **WHEN** 運用者が `test --model <型番> --group <ID>` を再実行する
- **THEN** 参照ファイルの指定グループだけが新結果世代を示し、別グループの参照と結果は保持される
- **AND** 試験準備済み画像は保持される

#### Scenario: REQ-013-S03 公開前の中断で旧結果を保持する

- **GIVEN** 旧結果への参照があり、新結果世代の作成中または参照ファイルの切替前である
- **WHEN** 書込み失敗またはプロセス中断が起こり、次の型番コマンドが起動する
- **THEN** 旧参照と旧結果を使用でき、未公開の新結果を現在の結果として扱わない

#### Scenario: REQ-013-S04 公開後の中断で新結果を保持する

- **GIVEN** 新結果世代の完成後、参照ファイルの切替が成功した
- **WHEN** プロセスが中断し、次の型番コマンドが起動する
- **THEN** 新参照が示す全結果を使用でき、旧世代と新世代を混在させない

#### Scenario: REQ-013-S05 不正な現行結果参照を拒否する

- **GIVEN** 現行参照の版・グループID・相対世代パスが不正、参照先が欠落、または参照ファイル・参照先がシンボリックリンクである
- **WHEN** システムが現行結果を読み戻すか、他グループの参照を引き継ぐ `test --model <型番> --group <ID>` を実行する
- **THEN** 不正な参照を理由付きで拒否し、管理外のファイルを読み書きしない

#### Scenario: REQ-013-S06 検査の旧再開フラグを拒否する

- **GIVEN** 有効な型番の設定と検査結果がある
- **WHEN** 運用者が `test --model <型番> --restart` を実行する
- **THEN** コマンドは未対応のオプションとして拒否し、現行参照と結果を変更しない

#### Scenario: REQ-013-S07 全グループ検査で不正な現行参照を更新する

- **GIVEN** 現行参照の内容・参照先が不正または参照ファイルがシンボリックリンクであり、結果ディレクトリの親領域と検査入力・学習成果物は安全で有効である
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** 旧参照とその参照先をたどらずに全グループの新結果を生成し、完成後に現行参照のファイルエントリを安全に置き換える
- **AND** 管理外のファイルを読み書きしない

#### Scenario: REQ-013-S08 検査以外のコマンドを妨げない

- **GIVEN** 現行参照が不正である
- **WHEN** 運用者が同じ型番の `check`、`train-pre`、`train` または `test-pre` を実行する
- **THEN** 現行参照の不備を理由に処理を拒否しない

#### Scenario: REQ-013-S09 現行グループ以外の結果を整理する

- **GIVEN** 全グループまたは指定グループに以前の検査結果がある
- **WHEN** 新しい結果の現行参照への切替が成功する
- **THEN** 現行参照に含まれる各グループの結果だけを保持し、参照されなくなったグループ結果と空になった世代領域を削除する
- **AND** 単独実行で選択しなかったグループの現行結果は保持する

#### Scenario: REQ-013-S10 整理の中断後に再試行する

- **GIVEN** 参照切替の前後に処理が中断し、未公開または参照されなくなった結果が残っている
- **WHEN** 次の型番コマンドが排他を取得する
- **THEN** 現行参照が有効なら参照中の結果を保持し、参照されない結果だけの整理を再試行する
- **AND** 現行参照が不正なら結果を削除せず、準備・学習コマンドの実行を妨げない
- **AND** 整理だけが失敗した場合は現行結果を維持して警告を記録し、次回も再試行できる

### Requirement: REQ-016 アプリ生成checkpointの契約照合

システムは、アプリが生成したcheckpointを用いて検査を開始する時に、保存された型番、グループID、スコア契約および暫定閾値を読み込み、現在の設定と照合しなければならない (MUST)。

#### Scenario: REQ-016-S01 一致するcheckpointで検査する

- **GIVEN** 型番、グループID、スコア契約および暫定閾値が設定と一致するアプリ生成checkpointがある
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** 契約照合を通過し、分割画像の検査が実行される

#### Scenario: REQ-016-S02 メタデータのないcheckpointを拒否する

- **GIVEN** 必要なメタデータを持たないcheckpointがある
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** 必要なメタデータがない理由を示して検査開始前にエラー終了する
- **AND** 運用者は正しい学習成果物を用意して再実行できる

#### Scenario: REQ-016-S03 別グループのcheckpointを拒否する

- **GIVEN** 要求グループと異なるグループIDを持つcheckpointがある
- **WHEN** 運用者がそのグループの検査を実行する
- **THEN** グループ不一致を示して推論前に拒否し、既存の結果を保持する

### Requirement: REQ-018 検査用閾値の選択と記録

システムは、運用者が型番のグループの検査を実行した時に、対象グループの検査用閾値が未指定または `null` なら学習由来の暫定閾値を、0以上1以下の数値なら指定値を判定へ使用し、使用値を結果に記録しなければならない(MUST)。

検査用閾値は `optuna_settings.threshold.value` と独立したグループ別設定とする。<br />
学習済み checkpoint、最良試行結果、型番設定にある暫定閾値の整合確認は、検査用閾値の指定にかかわらず維持する。<br />
異常スコアが使用閾値と等しい場合は `anomaly` とする。

#### Scenario: REQ-018-S01 検査用閾値が未指定なら暫定閾値を使用する

- **GIVEN** 暫定閾値と整合する学習成果物があり、検査用閾値を指定していない
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** システムは暫定閾値で分割画像を判定し、結果にその使用値を記録する

#### Scenario: REQ-018-S02 明示的な null なら暫定閾値を使用する

- **GIVEN** 有効な暫定閾値があり、検査用閾値が `null` である
- **WHEN** 運用者が検査を実行する
- **THEN** システムは暫定閾値で判定し、結果にその使用値を記録する

#### Scenario: REQ-018-S03 指定した検査用閾値を使用する

- **GIVEN** 暫定閾値と異なる0以上1以下の検査用閾値がある
- **WHEN** 運用者が検査を実行する
- **THEN** システムは指定した閾値で判定し、結果にその使用値を記録する
- **AND** 型番設定と学習成果物に保存した暫定閾値を変更しない

#### Scenario: REQ-018-S04 境界値を使用する

- **GIVEN** 検査用閾値が0または1である
- **WHEN** 運用者が検査を実行する
- **THEN** システムはその値を判定に使用し、スコアが使用閾値に等しければ `anomaly` と記録する

#### Scenario: REQ-018-S05 不正な検査用閾値を拒否する

- **GIVEN** 検査用閾値が0未満、1超、数値以外、または真偽値である
- **WHEN** 運用者が検査を実行する
- **THEN** システムは設定項目と理由を示して推論前に入力不備として拒否し、不完全な検査結果を正常な結果として保存しない

#### Scenario: REQ-018-S06 暫定閾値の不整合を上書き値で隠さない

- **GIVEN** 検査用閾値が有効でも、グループ設定・checkpoint・最良試行結果の暫定閾値が一致しない
- **WHEN** 運用者が検査を実行する
- **THEN** システムは不一致を示して推論前に拒否し、成果物の確認を促す

### Requirement: REQ-019 型番別ヒートマップ表示範囲の指定

システムは、運用者が型番のグループの検査を実行する時に、グループ別設定に明示したヒートマップ表示範囲の下限と上限を検査画像間で共通して使用しなければならない (MUST)。

下限と上限は有限の数値で、下限は上限より小さくなければならない。異常マップの値域を異常スコアの `0`〜`1` に限定しない。表示範囲は異常スコア、暫定閾値、検査用閾値と独立する。

#### Scenario: REQ-019-S01 有効な表示範囲を使用する

- **GIVEN** グループ別設定に有限の数値で下限が上限より小さい表示範囲がある
- **WHEN** 運用者がその型番のグループの検査を実行する
- **THEN** システムは同じ表示範囲をその検査の全分割画像の可視化に使用する
- **AND** 異常スコアと判定閾値を表示範囲から変更しない

#### Scenario: REQ-019-S02 未指定または不正な表示範囲を拒否する

- **GIVEN** グループ別設定の表示範囲が未指定、片側だけ指定、数値以外、真偽値、非有限値、または下限が上限以上である
- **WHEN** 運用者がその型番のグループの検査を実行する
- **THEN** システムは不正な項目と理由を示して推論前に入力不備として拒否する
- **AND** 不完全な検査結果を正常な結果として保存しない
- **AND** 運用者は表示範囲を修正して再実行できる
