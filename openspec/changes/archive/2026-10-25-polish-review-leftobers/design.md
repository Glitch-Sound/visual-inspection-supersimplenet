## 背景・前提

設定は `src/app/common/config.py` の `GroupRangeConfig` で検証され、5コマンドの共通実行器は `ValueError` を終了コード2に変換する。<br />
現行の閾値検証は `math.isfinite` に巨大整数を直接渡すため、`OverflowError` が共通の入力不備処理に届かない。<br />
パスの構成要素は `src/app/common/paths.py` の共通関数でシンボリックリンクを拒否する。エラーには現在も末尾にパスがあるが、先頭の `prepared input` は設定・成果物にも使われる。<br />
学習は `src/app/model_training/cli.py` でストレージ接続を所有する。成功時は公開前に閉じるが、失敗時は `except` の一時領域削除の後に `finally` で閉じる。`create_study` には接続を渡さず内部で生成する経路がある。<br />
ユーザー指定により旧準備・学習・検査成果物の互換性と移行は不要で、変更後に全工程を再実行する。

## 目標・対象外

### 目標

- 巨大整数の検査閾値を全CLIで終了コード2へ統一する。
- 拒否したシンボリックリンクのパスをエラーの主語として明示する。
- 学習失敗時を含め、ストレージ接続の終了後に一時探索領域を削除する。
- `create_study` の呼び出し元がストレージ接続を必ず所有する。

### 対象外

- 閾値の範囲、リンク拒否方針、探索アルゴリズム、結果形式の変更。
- 旧成果物の移行・互換処理。全工程の再実行を前提とするため。

### 処理フロー

1. 5コマンドの共通入口はパスを検証し、対象のシンボリックリンクがあればそのリンクのパスを含む入力不備を返す。リンク先は変更しない。
2. 設定読込は全グループの分割条件を検証する。巨大整数の検査閾値は `ValueError` 相当の入力不備とし、グループ・分割・項目を示す。成果物を更新せず終了コード2で終わる。
3. `train` はグループごとに一時探索領域とストレージ接続を作る。接続を `create_study` に必須引数として渡し、内部で別の接続を生成させない。
4. 探索と公開準備が成功したら接続を閉じてから公開する。探索中・公開前に失敗したら、接続を閉じてから失敗グループの一時領域を削除し、旧成果物を保持して失敗グループと理由を返す。
5. 運用者は原因修正後に `check`、`train-pre`、`train`、`test-pre`、`test` を全て再実行し、結果を読み戻す。

## 技術判断

### 判断: 巨大整数の数値検証

- **状態**: 確定。
- **採用内容**: `math.isfinite` の `OverflowError` を有限数値違反の `ValueError` に変換する。既存の型・範囲検証と項目別エラーを維持する。
- **根拠**: `synthetic_anomaly` と `heatmap_range` に同じ境界処理があり、共通CLIが `ValueError` を入力不備へ変換する。
- **代替案**: 桁数の上限を新設する案は仕様外の制限を追加するため採用しない。
- **実装規則 / 不変条件**: 真偽値、文字列、無限大、範囲外の値の既存扱いを維持する。
- **影響**: `common/config.py` と5コマンドの試験。

### 判断: シンボリックリンクのエラー

- **状態**: 確定。
- **採用内容**: 共通パス検証の文言を、用途を限定しない `symlink path is not allowed: <リンク自体のパス>` に変える。理由は英語で示し、共通CLIが日本語の「入力不備」を付けて表示する。
- **根拠**: 同じ検証関数が設定・準備・成果物のパスに使われる。検出した構成要素の `current` がリンク自体のパスである。
- **代替案**: 呼び出し元ごとに用途名を渡す案は重複が増え、対象パスの特定には不要。
- **実装規則 / 不変条件**: 拒否条件とリンク先不変を維持し、リンク先の解決パスでなく拒否したリンクのパスを示す。
- **影響**: `common/paths.py` とリンク拒否試験。

### 判断: 探索接続の所有と終了順序

- **状態**: 確定。
- **採用内容**: `create_study` のストレージハンドルを必須にし、内部生成分岐を削除する。学習CLIが作成・終了を所有し、`finally` で接続終了、外側の失敗処理で一時領域削除を行う。成功時は公開前に閉じる。
- **根拠**: 現行の失敗処理では一時領域削除が接続終了より先に実行される。必須ハンドルなら閉じられない接続を作らない。
- **代替案**: `except` 内にも接続終了を複写する案は成功時・失敗時の二重終了や経路漏れを招く。
- **実装規則 / 不変条件**: 一時領域を削除・公開する前に `remove_session` と `engine.dispose` を完了する。グループごとの失敗理由と旧成果物を維持する。
- **影響**: `model_training/cli.py`、`search.py`、呼び出し側の既存試験。
