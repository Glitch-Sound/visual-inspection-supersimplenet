## MODIFIED Requirements

### Requirement: REQ-010 分割画像のスコア・判定・可視化

システムは、運用者が型番の検査を要求した時に、対象グループの学習済みパラメータをそのグループの全分割IDへ適用し、分割画像ごとの異常スコア、当該分割の閾値との比較結果および結果画像を保存しなければならない(MUST)。<br />
試験時は閾値算出時と同じ決定的前処理を使い、PostProcessorを無効にしたSuperSimpleNetの `pred_score` を異常スコアとする。`pred_score >= threshold` を `anomaly`、それ以外を `normal` とする。ヒートマップには同じ推論のPostProcessor適用前の `anomaly_map` を分割画像サイズへリサイズして使用する。異常分割は当該分割の `heatmap_range` で色付けし、範囲外は端の色に固定する。同じ表示範囲の同じ値には同じ色を割り当て、画像ごとの最小・最大値で色を変えない。

#### Scenario: REQ-010-S01 正常な分割画像を記録する

- **GIVEN** 有効な学習成果物と分割条件があり、分割画像の `pred_score` が使用閾値未満である
- **WHEN** 運用者が検査を実行する
- **THEN** 分割画像のスコアと `normal` 判定、入力画素を変更していない結果画像が保存される

#### Scenario: REQ-010-S02 異常な分割画像を可視化する

- **GIVEN** 有効な学習成果物と分割条件があり、分割画像の `pred_score` が使用閾値以上である
- **WHEN** 運用者が検査を実行する
- **THEN** スコアと `anomaly` 判定が保存され、元画像を左、当該分割の表示範囲によるヒートマップ付き画像を右に並べた結果画像が保存される

#### Scenario: REQ-010-S03 閾値算出と同じ前処理を使用する

- **GIVEN** bilinear補間、antialiasおよびImageNet正規化を設定したSuperSimpleNetがある
- **WHEN** 探索、暫定閾値算出または試験推論を実行する
- **THEN** モデルに設定した同一の決定的前処理を使用し、別ライブラリによる近似前処理と学習用データ拡張を試験推論に適用しない

#### Scenario: REQ-010-S04 画像間で色を比較する

- **GIVEN** 同じ表示範囲を指定した分割の異なる異常マップがある
- **WHEN** 運用者が検査を実行する
- **THEN** 同じ異常マップ値は同じ色、範囲外は端の色になり、スコアと判定は表示範囲によって変わらない

### Requirement: REQ-012 元画像単位の検査結果契約

システムは、検査対象の元画像・グループごとに、元画像名、型番、グループID、対象分割ID、使用checkpoint、スコア契約、各分割ID・画像名・異常スコア・判定・結果画像・エラー・使用閾値・閾値の出どころ・表示範囲、グループ内の元画像判定、処理日時、位置合わせ結果、エラー、警告および共通実行記録を機械可読な結果として保存しなければならない(MUST)。<br />
グループ単位の `threshold` と `heatmap_range` は結果に含めない。閾値の出どころは `provisional` または `configured` とする。推論不能な分割にも使用予定の閾値・出どころ・表示範囲を記録し、スコアを `null` とする。スコア源は `supersimplenet.pred_score`、PostProcessorは無効とする。共通実行記録にはコマンド、型番、処理したグループID、開始・終了日時、コマンド単位の処理時間、終了コード、終了状態、デバイス、OS・Python、主要依存関係、警告、エラーを含める。

#### Scenario: REQ-012-S01 追跡可能な JSON 結果を保存する

- **GIVEN** 有効な検査入力と、正常・異常・未判定・一部分割エラーのいずれかを含む元画像がある
- **WHEN** システムが元画像の検査結果を確定する
- **THEN** 各分割の使用閾値、`provisional` または `configured`、表示範囲、判定と、従来どおり集約した元画像判定を含むJSONが保存される
- **AND** 判定不能な分割のスコアは `null` で、グループ直下の旧閾値・表示範囲項目はない

#### Scenario: REQ-012-S02 不正な結果契約を拒否する

- **GIVEN** 分割の閾値・出どころ・表示範囲が欠落または不正、旧グループ単位項目がある、スコア契約・判定・実行記録・日時のいずれかが不正な結果がある
- **WHEN** システムが元画像結果を生成または読み戻す
- **THEN** 不正な項目と理由を示して結果契約を拒否し、正常な検査結果として扱わない

#### Scenario: REQ-012-S03 同じstemの元画像結果を区別して保存する

- **GIVEN** 同じstemで拡張子だけが異なる複数の試験元画像がある
- **WHEN** システムが検査結果を保存する
- **THEN** 拡張子付き元画像名を含む一意なJSON名と分割結果画像名を使い、互いを上書きしない

#### Scenario: REQ-012-S04 不正な試験manifestのパスと対応関係を拒否する

- **GIVEN** 試験manifestの型番、元画像名・分割画像名のパス要素や重複、分割の元画像参照、分割ID、拡張子付き画像名と2桁以上のIDから決まる分割名の不整合、または準備領域・manifest・参照分割画像のシンボリックリンクがある
- **WHEN** 運用者が検査を実行する
- **THEN** 不正な項目と理由を示して推論前に拒否し、管理外のファイルと既存結果を変更しない

#### Scenario: REQ-012-S05 グループの結果を区別する

- **GIVEN** 同じ元画像・分割IDを異なる条件の二つのグループで検査する
- **WHEN** 運用者が全グループの検査を実行する
- **THEN** 各グループの結果は別々に保存され、各分割の使用閾値・出どころ・表示範囲を識別できる

#### Scenario: REQ-012-S06 準備時と異なる試験設定を拒否する

- **GIVEN** 試験準備後に分割位置、画像サイズまたは位置合わせ条件が変わった
- **WHEN** 運用者が検査を実行する
- **THEN** 準備指紋の不一致を推論前に示し、既存結果を保持して `test-pre` の再実行を案内する

### Requirement: REQ-018 検査用閾値の選択と記録

システムは、運用者がグループを検査した時に、各分割の `inspection_threshold` が `null` なら整合確認済みのグループ暫定閾値を、0以上1以下の有限数値ならその指定値を使用し、使用値と出どころを分割結果へ記録しなければならない(MUST)。<br />
暫定閾値は `group_detail`、checkpoint、最良試行で整合を確認する。使用閾値との一致も `anomaly` とする。

#### Scenario: REQ-018-S01 検査用閾値が未指定なら暫定閾値を使用する

新形式では「未指定」をキーの欠落と扱い、暫定閾値を使用するには `null` を明示する。

- **GIVEN** 分割の `inspection_threshold` が欠落している
- **WHEN** 運用者が検査を実行する
- **THEN** グループIDと分割ID、必須項目の欠落を示して入力不備として拒否し、既存結果を保持する

#### Scenario: REQ-018-S02 明示的な null なら暫定閾値を使用する

- **GIVEN** 分割の `inspection_threshold` が `null` である
- **WHEN** 運用者が検査を実行する
- **THEN** グループの暫定閾値で判定し、分割結果に使用値と `provisional` を記録する

#### Scenario: REQ-018-S03 指定した検査用閾値を使用する

- **GIVEN** 分割の指定閾値が暫定閾値と異なる
- **WHEN** 運用者が検査を実行する
- **THEN** 指定値で判定し、分割結果に使用値と `configured` を記録し、暫定閾値を変更しない

#### Scenario: REQ-018-S04 境界値を使用する

- **GIVEN** 分割の指定閾値が0または1である
- **WHEN** 運用者が検査を実行する
- **THEN** その値を使い、スコアが等しければ `anomaly` と記録する

#### Scenario: REQ-018-S05 不正な検査用閾値を拒否する

- **GIVEN** 分割の閾値が範囲外、非有限、数値以外、または真偽値である
- **WHEN** 運用者が型番のいずれかのコマンドを実行する
- **THEN** グループID・分割ID・理由を示して入力不備として拒否し、既存成果物を更新しない

#### Scenario: REQ-018-S06 暫定閾値の不整合を上書き値で隠さない

- **GIVEN** 指定閾値が有効でも、グループ設定・checkpoint・最良試行の暫定閾値が一致しない
- **WHEN** 運用者が検査を実行する
- **THEN** 不一致を示して推論前に拒否し、成果物の確認を促す

### Requirement: REQ-019 型番別ヒートマップ表示範囲の指定

システムは、運用者がグループの検査を実行した時に、各分割に明示した有限数値の `heatmap_range.min < heatmap_range.max` をその分割の可視化に使用しなければならない(MUST)。<br />
異常マップ値を0～1へ制限せず、表示範囲はスコア・閾値・判定を変更しない。

#### Scenario: REQ-019-S01 有効な表示範囲を使用する

- **GIVEN** 同じグループの分割に異なる有効な表示範囲がある
- **WHEN** 運用者が検査を実行する
- **THEN** 各分割の指定範囲で色付けし、分割結果に使用範囲を記録する
- **AND** 表示範囲だけの変更はスコアと判定を変更しない

#### Scenario: REQ-019-S02 未指定または不正な表示範囲を拒否する

- **GIVEN** 分割の表示範囲が欠落、片側だけ、数値以外、真偽値、非有限、または `min >= max` である
- **WHEN** 運用者が型番のいずれかのコマンドを実行する
- **THEN** グループID・分割ID・理由を示して入力不備として拒否し、既存成果物を更新しない

## ADDED Requirements

### Requirement: REQ-036 検査開始時の分割別閾値表示

システムは、運用者が検査を開始した時に、各対象グループ・分割IDについて使用閾値と `provisional` または `configured` の出どころを表示しなければならない(MUST)。

#### Scenario: REQ-036-S01 分割ごとの使用値を確認する

- **GIVEN** 一つのグループに暫定閾値を使う分割と設定閾値を使う分割がある
- **WHEN** 運用者が検査を開始する
- **THEN** グループID・分割IDごとに使用値と出どころが表示され、結果JSONの値と一致する
