## MODIFIED Requirements

### Requirement: REQ-007 型番別モデル・閾値・探索結果の保存

システムは、探索完了時に、対象グループの全分割 ID を検査できる型番・グループ別の学習済みパラメータ、最良試行の条件と評価値、学習済みパラメータとの対応、および学習対象画像の`pred_score`分布の99パーセンタイル値である暫定閾値を保存しなければならない(MUST)。<br />
暫定閾値は、最良試行のモデルをevalモード、データ拡張なし、探索時と同じ決定的前処理で学習集合へ再推論して算出しなければならない(MUST)。<br />
checkpoint、最良試行結果および型番設定の対象グループには、スコア源が`supersimplenet.pred_score`でPostProcessorが無効であるスコア契約と、同一の暫定閾値を保存しなければならない(MUST)。<br />
checkpointには型番とグループID、スコア契約および暫定閾値を保存し、最良試行結果には試行番号、探索条件、目的値、checkpoint参照、スコア契約、暫定閾値、学習・検証データ集合、seedおよび主要依存関係の版を保存しなければならない(MUST)。<br />
対象グループの`score.source`と`threshold.score_source`は一致し、`anomalib_post_processor`は`false`でなければならず、違反する設定は学習開始前に拒否しなければならない(MUST)。<br />
対象グループの探索履歴とcheckpointは、全成果物の作成が成功するまで旧成果物を変更せず、成功後に旧成果物を削除して新成果物へ置き換える。公開途中に欠落・不整合が生じても旧成果物は復旧しない。

#### Scenario: REQ-007-S01 最良モデルと暫定閾値を保存する

- **GIVEN** 全探索試行が完了して最良試行が決定している
- **WHEN** 学習処理が完了する
- **THEN** 型番・グループ別のcheckpointと最良試行結果に同じ暫定閾値、スコア契約、対応情報が保存される
- **AND** 対象グループの型番設定へ暫定閾値が記録される

#### Scenario: REQ-007-S02 事前学習重みを再利用する

- **GIVEN** 指定された `wide_resnet50_2` の事前学習重みがキャッシュに存在する
- **WHEN** 運用者が学習を実行する
- **THEN** 保存済みの重みを利用し、同じ重みを再ダウンロードしない
- **AND** キャッシュがない場合だけ取得して以後の実行用に保持する

#### Scenario: REQ-007-S03 公開前の失敗と公開途中の欠落を区別する

- **GIVEN** 対象グループの旧探索履歴、checkpoint、型番設定がある
- **WHEN** 新成果物の作成途中で失敗または中断する
- **THEN** 旧学習成果物と型番設定は変更されず、失敗理由が示される
- **AND** 旧成果物の削除後から新成果物公開までに中断した場合は復旧せず、後続の利用前に欠落・不整合を拒否して再学習を促す

#### Scenario: REQ-007-S04 不整合な最良試行結果を拒否する

- **GIVEN** 最良試行結果の型番、checkpoint参照、スコア契約または閾値が設定・checkpointと一致しない、または探索条件の型が不正である
- **WHEN** 運用者が検査を実行する
- **THEN** 不一致項目を示してモデル生成・推論前に拒否し、再学習を促す

#### Scenario: REQ-007-S05 複数グループの閾値を独立に保存する

- **GIVEN** 二つのグループを異なる学習条件で学習できる
- **WHEN** 運用者が両グループの学習を実行する
- **THEN** 各グループのcheckpoint、最良試行結果、設定にグループ別の暫定閾値が整合して保存される
- **AND** 一方の保存によって他方の閾値は変わらない

#### Scenario: REQ-007-S06 擬似異常の設定値を両成果物へ記録する

- **GIVEN** グループの擬似異常範囲に明示値と省略項目がある
- **WHEN** 運用者がそのグループの `train` を完了する
- **THEN** 適用された全範囲が checkpoint のメタデータと `best_trial.json` の両方に同じ値で記録される

### Requirement: REQ-008 毎回の新規探索と学習

システムは、運用者が `train` を実行した時に、対象グループの探索履歴を毎回新規に作り、探索と学習を最初から行わなければならない(MUST)。<br />
学習の新成果物を公開するまでは旧成果物を維持する。

#### Scenario: REQ-008-S02 再学習で派生成果物を置き換える

- **GIVEN** 対象グループの旧探索結果と旧モデルが存在する
- **WHEN** 運用者が `train --model <型番> --group <ID>` を実行する
- **THEN** 既存探索履歴を使わず新規の探索と学習を行い、全処理の成功後に対象グループの探索結果とモデルを置き換える
- **AND** 元画像、他グループの成果物、事前学習重みのキャッシュは削除しない

#### Scenario: REQ-008-S03 全グループ学習の途中失敗を示す

- **GIVEN** 一つのグループの学習が完了し、後続グループの学習が失敗する
- **WHEN** 運用者が `train --model <型番>` を実行する
- **THEN** コマンドは失敗グループIDと理由を示してエラー終了する
- **AND** 完了済みグループの新成果物と失敗したグループの旧成果物を保持し、失敗したグループを修正して再実行できる

#### Scenario: REQ-008-S04 残った一時領域を破棄する

- **GIVEN** 前回の学習中断で対象型番の別グループにも一時領域が残っている
- **WHEN** 運用者が `train` を再実行する
- **THEN** 対象型番の管理対象一時領域をグループを問わず削除し、旧探索履歴を再開せず最初から探索する

### Requirement: REQ-034 擬似異常範囲の入力不備の拒否

システムは、擬似異常範囲が `noise_std: 0 < min <= max`、`perlin_threshold: 0 <= min <= max < 1`、`perlin_scale_exponent: 整数で 0 <= min <= max <= 5` のいずれかを満たさない場合、学習開始前に入力不備として拒否しなければならない(MUST)。数値は有限値とし、真偽値を数値として受け付けない。設定を修正した後は再実行できる。

#### Scenario: REQ-034-S01 範囲の境界と順序を検証する

- **GIVEN** いずれかの項目で範囲外、逆順、または非有限の端点が指定されている
- **WHEN** 運用者が学習を開始する
- **THEN** 入力不備の理由が示され、探索と学習成果物の更新は始まらない
- **AND** 運用者は設定を修正して再実行できる

#### Scenario: REQ-034-S02 指数の非整数と不正な型を拒否する

- **GIVEN** 指数の端点に小数、またはいずれかの端点に真偽値などの不正な型が指定されている
- **WHEN** 運用者が学習を開始する
- **THEN** 入力不備として拒否され、既存の学習成果物は更新されない

#### Scenario: REQ-034-S03 巨大な整数を入力不備として扱う

- **GIVEN** 擬似異常範囲の端点に有限の浮動小数へ変換できない巨大な整数がある
- **WHEN** 運用者が型番のコマンドを実行する
- **THEN** 入力不備として項目を示し、未処理例外では終了しない

## ADDED Requirements

### Requirement: REQ-038 探索履歴を読み戻せる状態で公開する

システムは、運用者が学習を完了した時に、公開された探索履歴を次回の確認時に読み戻せる状態にしなければならない(MUST)。

#### Scenario: REQ-038-S01 学習後に探索履歴を読み戻す

- **GIVEN** 探索と学習が完了したグループがある
- **WHEN** 運用者が保存された探索履歴を読み戻す
- **THEN** 最良試行を含む完了済み履歴を参照できる
