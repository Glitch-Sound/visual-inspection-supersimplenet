## 背景と現行業務フロー

現行リポジトリは Python CLI の雛形であり、外観検査、画像の位置合わせ・分割、モデル学習、評価結果の記録に対応する業務フローは存在しない。正式仕様も未登録であるため、正常として提供された画像を使って異常検出モデルを評価し、本番利用の検討材料を得ることができない。

現時点で確認できる入力と判断は次のとおりである。

1. 型番ごとに、主に正常と考えられる大容量画像が提供される。ただし正解ラベルはなく、提供画像にも異常が混在する可能性がある。
2. 評価に利用できない画像または分割範囲は、運用者がブラックリストとして指定する必要がある。
3. 初期モデルは評価用途であり、異常の検出状況および正常と考えられる画像での異常判定の発生状況を評価者が確認する。
4. 検出性能、誤検出および本番利用可否の数値基準は未決であり、初期評価結果を得た後に評価者が決定する。

## 利用者と運用者

| 役割 | 利用場面 | 目的・必要な判断 |
| --- | --- | --- |
| 運用者 | 型番設定、画像準備、学習・再学習、検査・再検査を実行するとき | 分割位置、ブラックリスト、学習条件を管理し、失敗・未判定時の復旧と旧成果物の退避要否を判断する |
| 評価者 | 初期モデルの検査結果を確認するとき | 異常の検出状況と、正常と考えられる画像での異常判定の発生状況を確認し、追加評価または本番利用検討へ進めるか判断する |

運用者と評価者が同一人物か別担当かは規定しない。ただし、評価結果を作成する責務と本番利用可否を判断する責務は区別する。

## 解決する課題

大容量画像をそのまま比較できず、検査対象の位置も固定されていないため、型番ごとの位置合わせと一貫した分割が必要である。また、正常とされた画像にも異常が混在し得る状態で学習対象を選別し、限られた正常画像から評価用モデルと暫定閾値を再現可能に生成する手段がない。

この状態を放置すると、分割画像と元画像の対応、学習対象、判定条件、モデルと評価結果の対応を追跡できず、評価者が初期モデルの妥当性を判断できない。

## 変更後の業務フロー

1. 運用者は型番を指定し、基準画像、分割範囲、位置合わせ条件、ブラックリスト、学習・探索条件およびデータ拡張条件を設定する。
2. 運用者は基準画像に分割範囲と分割 ID を重ねた確認画像を生成し、範囲が検査対象を覆っているか確認する。
3. 運用者は学習準備を実行する。システムは各学習画像を基準画像へ位置合わせし、ブラックリストを除外して分割画像を生成する。位置合わせ失敗は学習対象から除外して警告し、範囲外の分割指定はエラーとして中止する。
4. 運用者は学習を実行する。システムは元画像単位で学習用と検証用に分離し、正常画像の検証スコア分布を暫定指標として学習条件を探索する。最良条件、評価値、型番ごとの学習済みパラメータおよび暫定閾値を対応付けて保存する。
5. 運用者は試験準備を実行する。システムは試験画像を位置合わせして分割し、元画像と分割画像を追跡可能な名称で保存する。位置合わせできない画像は、後続の検査で未判定として扱える状態にする。
6. 運用者は検査を実行する。システムは型番に対応する単一の学習済みパラメータと閾値を全分割画像へ適用し、分割単位のスコア・判定・可視化結果と、元画像単位に集約した判定を記録する。
7. 分割画像が一つでも異常なら元画像を異常とし、判定可能な全分割画像が正常の場合のみ元画像を正常とする。位置合わせ失敗などにより一つでも判定不能なら、異常が検出されていない限り元画像を未判定とし、原則として再撮影へ引き継ぐ。
8. 評価者は保存された結果を確認し、異常の検出状況と正常と考えられる画像での異常判定の発生状況から、追加データ収集、再学習、再検査または本番利用検討への移行を判断する。

## 対象範囲

### 対象

- 型番ごとの設定による位置合わせ、分割範囲確認、学習・試験画像の生成、および学習時ブラックリスト除外
- 正常画像中心の初期データを使った評価用モデルの学習、学習条件の自動探索、探索再開、および暫定閾値の決定
- 学習時のみの設定可能なデータ拡張と、元画像単位での学習・検証分離
- 型番ごとの一つの学習済みパラメータを用いた全分割画像の検査、分割結果と元画像結果の保存、および異常箇所の可視化
- GPU 利用可能時の GPU 実行、利用不能時の CPU 実行、Ubuntu 24.04 LTS と Windows 11 での再現可能な環境記録
- 明示的な再学習・再検査時の対象成果物の再生成と、通常の中断後再開の区別

### 対象外

- 初期段階での本番利用承認。検出性能・誤検出の数値目標が未決であり、初期評価後に別途判断するため
- 異常画像と正解ラベルを必須とする教師あり評価、および閾値とデータ拡張条件を含む同時最適化。将来拡張可能な境界は設けるが、初期段階では実施しない
- 撮影装置との自動連携、結果通知、アクセス制御、ネットワークサービス化。入力資料に要求がないため
- 旧モデル・旧結果の恒久保管方式。明示的な再生成前に退避するかは運用者判断であり、保管制度は未合意のため

## 運用開始の受け入れ条件

- 運用者が型番を指定して、分割位置確認、学習準備、学習、試験準備、検査を順に実行し、各処理の結果、処理時間、警告・エラーを確認できる。
- 学習対象のブラックリスト除外、元画像単位の学習・検証分離、学習時だけのデータ拡張、探索の中断後再開を自動試験で確認できる。
- 分割画像のスコア・判定・可視化結果と、使用モデル・閾値・位置合わせ結果を含む元画像単位の結果を追跡でき、集約判定規則を自動試験で確認できる。
- 位置合わせ失敗、分割範囲外、設定不備、モデル不足の各結果と復旧操作が運用者に明示され、未判定画像を再撮影へ引き継げる。
- Ubuntu 24.04 LTS および Windows 11 の実機で、採用依存関係を固定したうえで GPU による学習・推論・結果保存と、GPU を利用できない状態での CPU 実行を確認し、その環境と結果を運用記録に残す。
- 初期評価の開始には、評価用データ、型番設定、学習済みパラメータ、閾値および検査結果の対応が確認できることを必須とする。本番利用開始には、評価者が別途決定する検出性能・誤検出の数値目標と承認条件を満たすことを必須とし、この change の完了だけでは本番利用可としない。

## 変更する能力

### 新規能力

- `visual-inspection/image-preparation`: 運用者が型番ごとの位置合わせ・分割条件とブラックリストを管理し、学習用・試験用の追跡可能な分割画像を準備できる能力
- `visual-inspection/model-training`: 運用者が正常画像中心のデータから学習条件を探索し、型番ごとの評価用モデル、探索結果および暫定閾値を再現可能に生成・再開できる能力
- `visual-inspection/model-evaluation`: 運用者と評価者が分割単位と元画像単位の検査結果、未判定、可視化および実行環境を確認し、再撮影・追加評価・本番利用検討を判断できる能力

### 変更する既存能力

- なし。既存の正式仕様は登録されていない。

## 影響範囲

- **利用者・業務**: 型番設定、画像準備、学習、検査、失敗時の復旧、評価者による判定という新しい運用フローを追加する。本番利用の承認フローは別途確定が必要である。
- **API・外部連携**: ローカル CLI を追加する。撮影装置、通知先、外部 API との連携は追加しない。
- **データ**: 元画像を保持したまま、分割画像、確認画像、学習済みパラメータ、探索状態、閾値、検査画像および JSON 結果を型番単位で追加する。明示的な再生成では対象の派生成果物を置き換える。
- **品質・運用**: Python 3.13、対象 OS、GPU/CPU の各経路に対応する依存関係と実行結果の固定・記録が必要になる。性能・精度の本番基準は初期評価後まで未決であり、本番利用開始を制約する。
