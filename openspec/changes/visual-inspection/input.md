# 入力仕様

## 1. 目的
`SuperSimpleNet` を利用した `外観検査` を行いたい。<br />
`Optuna` にて `ハイパーパラメータ` は自動的に最適化する仕組みを取り込みたい。
初期モデルは評価用とし、異常の検出状況と正常と考えられる画像での異常判定の発生状況を確認する。<br />
評価結果が十分と評価者が判断した場合に、本番利用を検討する。


## 2. 前提

### 2.1. 環境
- `GPU` は `NVIDIA` の `GeForce RTX 50シリーズ` を利用する
- `Ubuntu 24.04 LTS` と `Windows 11`（いずれも x86-64）で動作させたい
- `Python 3.13` を利用する
- 初期検証では `PyTorch 2.13.0`、`torchvision 0.28.0` の `CUDA 13.0` 対応版、および `Anomalib 2.6.2` を候補とする
- 各OSでGPUに対応する安定版の`NVIDIA`ドライバを使用する。`CUDA 13.0`対応版`PyTorch`の最低要件は`Ubuntu`で`580.65.06`、`Windows`で`580.88`とし、実際に採用するドライバ版は実機検証後に固定する
- `GPU` が利用できない状態でも学習、推論処理は動作するようにしたい
- 学習、推論、結果保存、`GPU`から`CPU`への切り替えを両OSで確認し、採用する依存関係の版をロックファイルと運用記録に残す

### 2.2. 画像
- サイズが非常に大きいため、分割する必要あり
- 分割位置は `JSON` 等で管理したい
- 検査対象の画像内の位置は固定されていないため、位置合わせが必要
- 初期段階で利用できるのは正常として提供された画像が中心で、正解ラベルはない
- 正常として提供された画像にも異常が含まれる可能性があるため、学習に使わない画像・分割範囲を指定する仕組み(`ブラックリスト`)が必要
- 検査対象は型番(以降、`XX`とも表現)ごとに形状が異なる

### 2.3. モデル
- `SuperSimpleNet` を利用する
- `Anomalib` を活用したい
- `ハイパーパラメータ` など学習時の設定は `設定ファイル` 等で変更できるようにする
- 初期段階では、正常として提供された画像からブラックリスト対象を除外し、以下の項目を `Optuna` で探索する
    - 学習率
    - バッチサイズ
    - エポック数
    - 特徴抽出層
    - 前処理条件
- 初期段階では、検証用に分けた学習対象画像の異常スコアの99パーセンタイル値を暫定的な探索指標とし、値を最小化する。この指標だけで異常の検出性能は判断しない
- 異常画像が用意できた段階では、正常画像と異常画像を利用した検証へ拡張できる構成とする
- 学習データが少ない場合、学習時に内部データ拡張を適用する
- データ拡張の種類と強度は型番(`XX`)ごとの設定ファイルで変更可能にする
- データ拡張は学習時だけ有効にし、検証時と試験時は無効にする

### 2.4. 事前学習重み
- 一旦は `wide_resnet50_2` を利用する
- ダウンロードしたバックボーンは指定フォルダに残すようにする

### 2.5. 学習済みパラメータ
- 分割された画像ごとではなく、1つの `学習済みパラメータ` で全分割画像の `外観検査` に対応したい
- `学習済みパラメータ` はファイルで管理可能とする
- `学習済みパラメータ` は型番(`XX`)ごとに管理する
- 分割画像ごとの検査結果と、元画像全体の検査結果の両方を記録する
- 分割画像が1つでも異常と判定された場合、元画像全体を不良と判定する
- 異常判定の閾値は型番(`XX`)ごとに設定および保存できるようにする
- 初期段階では正常画像の異常スコア分布から暫定閾値を決定する
- 異常画像を利用できる段階では、Optunaでモデルのハイパーパラメータと異常判定の閾値を同時に探索する
- 全分割IDを同じモデルに入力して検査する
- 分割画像の画像スコアに型番(`XX`)ごとの閾値を適用する
- 分割画像が1つでも閾値以上の場合、元画像全体を不良と判定する
- 暫定的な判定閾値は、学習後に学習対象画像から得た異常スコア分布の99パーセンタイル値とする

### 2.6. 評価と運用
- 初期モデルの判定結果は評価に使用し、評価者が異常の検出状況と正常と考えられる画像での異常判定の発生状況を確認する
- 検出性能や誤検出についての数値目標、本番利用の可否は評価結果を踏まえて決める。初期段階で数値目標を確定しない
- 未判定となった画像は原則として再撮影する。再撮影以外の扱いが必要な場合は評価者が判断する
- 明示的な再学習・再検査では、対象の旧モデルや生成済み画像・結果を削除して再生成する。旧成果物を別の場所へ保存するかは運用者が決める
- 元画像、型番設定、事前学習重みのキャッシュは再生成対象に含めない

ソース、学習データ、モデル、学習済みパラメータ、設定ファイルに絞った構成は以下とする。<br />

│   │       └── xxx.png             # 型番に紐づく試験用(正常/異常含む)の画像ファイル

│   │       └── xxx_nn.png          # 型番に紐づく学習用(正常)の画像ファイル

└── src/                            # ソース格納先

## 4. 設定ファイル

### 4.1. setting.ini
全体に関する設定を規定する。

- 学習・試験データの画像サイズ

```ini
[IMAGE]
SIZE = 500      # 切り出しサイズ(縦・横)
```


### 4.2. part_XX.json
型番(`XX`)ごとの設定を規定する。

- 位置合わせの基準ファイル
- 切り出し範囲(複数指定)
- ブラックリスト
- 学習設定

```json
{
    "_comment_base": "位置合わせの基準ファイル名(01_original_train内のファイル)",
    "base": "",

    "_comment_range": "切り出し範囲(複数指定可)",
    "range": [
        {
            "id": 0,
            "x":  0,
            "y":  0
        }
    ],

    "_comment_blacklist": "ブラックリスト(学習時のみ参照し、指定IDの画像は04_trainへ出力しない)",
    "blacklist": [
        {
            "image": "",
            "id": []
        }
    ],

    "_comment_optuna": "Optunaによる最適化パラメータの探索範囲などの設定",
    "optuna_settings": {
        "search": {
            "learning_rate": {},
            "batch_size": {},
            "epochs": {},
            "feature_layers": [],
            "preprocessing": {},
            "augmentation": {}
        },
        "threshold": null,
        "normal_only": {
            "percentile": 99,
            "train_ratio": 0.8,
            "validation_ratio": 0.2,
            "seed": 42
        },
        "execution": {
            "trials": 50,
            "seed": 42,
            "storage": "optuna/XX/study.db",
            "resume": true
        }
    },

    "_comment_augmentation": "学習時だけ適用するデータ拡張の種類と強度",
    "augmentation": {
        "enabled": true,
        "translation": {},
        "rotation": {},
        "brightness": {},
        "contrast": {},
        "color_temperature": {},
        "gamma": {},
        "sensor_noise": {},
        "blur": {}
    },

    "alignment": {
        "method": "ORB",
        "minimum_matches": 20,
        "confidence": 0.5
    }
}
```

座標はOpenCVの仕様に合わせ、原点を画像左上、`x`を右方向、`y`を下方向とする。
座標単位はピクセルとし、切り出し範囲は左上を含み右端・下端を含まない範囲として扱う。
`SIZE` は縦横が同じ正方形のピクセル数とする。<br />

ORBの`minimum_matches`は20、`confidence`はホモグラフィ推定時のインライア比率0.5を初期値とする。
実データに応じて型番(`XX`)ごとに変更可能にする。

## 5. コマンド
各コマンドは結果、処理時間、適切なログを見やすく出力すること。

### 5.1. 分割位置確認
学習、試験データをどのように分割するか確認する。
```bash
uv run check --model XX
```

`data/01_original_train/XX/` に格納され、`part_XX.json` の `base` にて指定された画像ファイル(`基準画像ファイル`)を利用する。<br />
以下の情報を利用し、切り出し範囲を可視化した画像ファイルを `data/03_check` へ出力する。

  - 切り出し開始位置 : `part_XX.json` の `range`
  - 切り出しサイズ　 : `setting.ini` の `IMAGE:SIZE` (縦・横)

`data/03_check` には `基準画像ファイル` に上記切り出し範囲を矩形で重ねた画像を保存する。<br />
矩形の左上にはラベルで `切り出し範囲のID` を描画する。


### 5.2. 学習準備
学習用(正常)の画像ファイルを設定ファイルに基づき、学習が行える画像を生成する。
```bash
uv run train-pre --model XX
```

`5.1. 分割位置確認` にて確定した切り出し範囲を元に、`data/01_original_train/XX/` に格納された画像をそれぞれ切り出し、`data/04_train/XX/` 配下に格納する。<br />
切り出し後のファイル名は元ファイルに切り出し範囲のID(2桁0埋め)のサフィックスを付与した名称とする。
```text
xxx_nn.png      # xxx: 元ファイル名, nn: 切り出し範囲のID(2桁0埋め)
```

元画像と分割画像は、元画像の拡張子を除いたファイル名と2桁0埋めの分割IDで対応付ける。
このファイル名規則を学習、試験、結果集約における正式な契約とする。<br />

なお、切り出す前に `特徴点(ORB)` による位置合わせを行う。<br />
各ファイルは `part_XX.json` の `base` にて指定された画像ファイル(`基準画像ファイル`)になるべく位置を合わせた上で切り出すこと。<br />
また、`part_XX.json` の `blacklist` にて指定された画像ファイル、切り出しIDに該当する場合はスキップすること。<br />

ORBによる位置合わせに失敗した場合は、該当画像を学習対象から除外し、警告ログを出力すること。
ORBの最低マッチ数と信頼度は、型番(`XX`)ごとの設定で変更可能にすること。<br />

切り出し範囲が画像範囲外にはみ出した場合、エラーとすること。


### 5.3. 学習
学習を行い、学習済みパラメータを生成する。
```bash
uv run train --model XX
```

`data/04_train/XX/` に格納された画像ファイルを利用し、学習を行う。<br />
`pretrained/` に事前学習済みモデルがダウンロードされていない場合、 ダウンロードし保管すること。<br />

`optuna` を利用し、ブラックリスト対象を除いた学習対象画像を学習用と検証用に分けて、以下の項目を探索すること。

元画像単位で学習用と検証用に分割し、初期値は学習用80%、検証用20%とすること。
学習用元画像からは全分割画像を学習に使用し、検証用元画像からは全分割画像を検証に使用すること。
分割画像単位で学習用と検証用を分割してはならない。<br />

    - 学習率
    - バッチサイズ
    - エポック数
    - 特徴抽出層
    - 前処理条件

初期段階では異常画像を必須とせず、正常として提供された画像の異常スコアが低く安定する設定を探索すること。
検証用に分けた学習対象画像の異常スコアの99パーセンタイル値を暫定指標として評価し、値を最小化する設定を採用すること。この値を異常の検出性能とみなさないこと。
型番(`XX`)ごとの暫定的な異常判定閾値も決定すること。<br />

学習データが少ない場合は、以下のデータ拡張を学習処理の内部で適用できること。

    - 微小な平行移動
    - 微小な回転
    - 明るさの変化
    - コントラストの変化
    - 色温度の変化
    - ガンマの変化
    - センサー由来のノイズ
    - 軽微なぼかし

元画像と `data/04_train/XX/` 配下の前処理済み画像は変更せず、データ拡張した画像を永続化しないこと。
データ拡張の種類と強度は、型番(`XX`)ごとの設定に従うこと。<br />

データ拡張の設定値は、平行移動を画像サイズに対する比率、回転を度、明るさとコントラストを変化率、
色温度をケルビン、ガンマを倍率、センサー由来ノイズを正規化画素値の標準偏差、ぼかしを奇数のカーネルサイズで指定する。

将来、異常画像と正解ラベルを利用できるようになった場合は、Optunaの評価処理を拡張し、モデルのハイパーパラメータと異常判定閾値を同時に探索できること。<br />
最終的に確定した学習済みパラメータは `weights/` に保存すること。
探索結果、探索条件、型番(`XX`)ごとの閾値は `optuna/XX/` に保存すること。
Optunaの初期試行回数は50回、乱数seedは42とし、探索結果を `optuna/XX/study.db` に保存すること。
探索が中断した場合は既存の探索結果を保持して再開できること。明示的に最初から再学習する場合は、対象型番の旧探索結果と旧モデルを削除して再生成すること。
最良試行の条件と評価値、学習済みパラメータへの対応を保存すること。<br />


### 5.4. 試験準備
試験用(正常/異常含む)の画像ファイルを設定ファイルに基づき、試験が行える画像を生成する。
```bash
uv run test-pre --model XX
```

`5.2. 学習準備` と同様となる。<br />
`5.1. 分割位置確認` にて確定した切り出し範囲を元に、`data/02_original_test/XX/` に格納された画像をそれぞれ切り出し、`data/05_test/XX/` 配下に格納する。<br />
切り出し後のファイル名は元ファイルに切り出し範囲のID(2桁0埋め)のサフィックスを付与した名称とする。
```text
xxx_nn.png      # xxx: 元ファイル名, nn: 切り出し範囲のID(2桁0埋め)
```

なお、切り出す前に `特徴点(ORB)` による位置合わせを行う。<br />
各ファイルは `part_XX.json` の `base` にて指定された画像ファイル(`基準画像ファイル`)になるべく位置を合わせた上で切り出すこと。<br />
試験については `blacklist` によるスキップ処理は不要となる。<br />

切り出し範囲が画像範囲外にはみ出した場合、エラーとすること。



### 5.5. 試験
学習済みパラメータを利用した検査を行い、結果、および試験結果画像を生成する。
```bash
uv run test --model XX
```

`data/05_test/XX/` に格納された画像ファイルを利用し、試験を行う。<br />
`weights/` に格納された学習済みパラメータを利用する。<br />

GPUが利用可能な場合はGPUを使用し、GPUが利用できない場合はCPUへ自動的に切り替えること。
GPUの有無にかかわらず、学習と推論を実行できること。<br />

試験時はデータ拡張を無効にし、入力画像を変更せずに検査すること。<br />

ORBによる位置合わせに失敗した場合は、エラーを明示し、該当画像の検査結果を未判定として記録すること。<br />

試験結果は `data/06_result/XX/` に格納すること。<br />
異常がなければ元ファイルのまま格納し、異常があれば異常箇所をヒートマップにて可視化すること。<br />
同じ型番を明示的に再検査する場合は、対象の旧結果画像とJSONを削除して再生成すること。<br />

分割画像ごとの異常スコア、判定結果、ヒートマップを記録すること。
分割画像が1つでも異常と判定された場合、元画像全体の判定結果を不良として記録すること。
元画像全体の判定結果と、判定に使用した型番(`XX`)ごとの閾値を記録すること。
試験結果の画像と同じ元画像単位でJSONを保存し、以下を記録すること。

    - 元画像名
    - 型番
    - 使用した学習済みパラメータ
    - 使用した閾値
    - 分割ID
    - 分割画像名
    - 分割画像の異常スコア
    - 分割画像の判定結果
    - 元画像全体の判定結果
    - 処理日時
    - 位置合わせ結果
    - エラーおよび警告

分割画像の判定結果には `normal`、`anomaly`、`undetermined`、`error` のいずれかを記録する。
ORB失敗などで判定できない分割画像のスコアは`null`とし、元画像全体も`undetermined`として記録する。
未判定の元画像は原則として再撮影の対象とし、必要に応じて評価者が次の扱いを決める。<br />
通常の判定では、分割画像に1つでも`anomaly`があれば元画像全体を`anomaly`とし、
異常がなく全分割画像が`normal`の場合に限り元画像全体を`normal`とする。<br />

データ拡張の種類と強度は、初期段階では型番(`XX`)ごとの設定ファイルで固定すること。
初期段階のOptunaではデータ拡張の有効・無効や強度を探索対象とせず、異常画像と正解ラベルが用意できた段階で探索対象へ追加できる構成とすること。
