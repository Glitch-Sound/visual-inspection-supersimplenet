# モデル評価仕様

## Purpose

運用者と評価者が型番別モデルを用いて分割画像と元画像の検査結果、異常箇所、未判定および実行環境を追跡し、再撮影・追加評価・再検査・本番利用検討の判断材料を得る能力を提供する。

## Requirements

### Requirement: REQ-009 実行デバイスの自動選択

システムは、学習または検査の開始時に利用可能な対応 GPU がある場合は GPU を選択し、利用できない場合は処理を中止せず CPU を選択して、選択したデバイスを運用者へ表示しなければならない(MUST)。

#### Scenario: REQ-009-S01 GPU を利用する

- **GIVEN** 対応 GPU と必要なドライバが利用可能である
- **WHEN** 運用者が学習または検査を実行する
- **THEN** システムは GPU を選択して処理を実行する
- **AND** 使用したデバイス情報を結果とログへ記録する

#### Scenario: REQ-009-S02 CPU へ切り替える

- **GIVEN** 対応 GPU がない、または GPU を利用できない
- **WHEN** 運用者が学習または検査を実行する
- **THEN** システムは CPU を選択して処理を継続する
- **AND** CPU へ切り替えた理由と使用デバイスを結果とログへ記録する

### Requirement: REQ-010 分割画像のスコア・判定・可視化

システムは、運用者が型番の検査を要求した時に、対象グループの学習済みパラメータをそのグループの全分割IDへ適用し、分割画像ごとの異常スコア、当該分割の閾値との比較結果および結果画像を保存しなければならない(MUST)。<br />
試験時は閾値算出時と同じ決定的前処理を使い、PostProcessorを無効にしたSuperSimpleNetの `pred_score` を異常スコアとする。`pred_score >= threshold` を `anomaly`、それ以外を `normal` とする。ヒートマップには同じ推論のPostProcessor適用前の `anomaly_map` を分割画像サイズへリサイズして使用する。異常分割は当該分割の `heatmap_range` で色付けし、範囲外は端の色に固定する。同じ表示範囲の同じ値には同じ色を割り当て、画像ごとの最小・最大値で色を変えない。

#### Scenario: REQ-010-S01 正常な分割画像を記録する

- **GIVEN** 有効な学習成果物と分割条件があり、分割画像の `pred_score` が使用閾値未満である
- **WHEN** 運用者が検査を実行する
- **THEN** 分割画像のスコアと `normal` 判定、入力画素を変更していない結果画像が保存される

#### Scenario: REQ-010-S02 異常な分割画像を可視化する

- **GIVEN** 有効な学習成果物と分割条件があり、分割画像の `pred_score` が使用閾値以上である
- **WHEN** 運用者が検査を実行する
- **THEN** スコアと `anomaly` 判定が保存され、元画像を左、当該分割の表示範囲によるヒートマップ付き画像を右に並べた結果画像が保存される

#### Scenario: REQ-010-S03 閾値算出と同じ前処理を使用する

- **GIVEN** bilinear補間、antialiasおよびImageNet正規化を設定したSuperSimpleNetがある
- **WHEN** 探索、暫定閾値算出または試験推論を実行する
- **THEN** モデルに設定した同一の決定的前処理を使用し、別ライブラリによる近似前処理と学習用データ拡張を試験推論に適用しない

#### Scenario: REQ-010-S04 画像間で色を比較する

- **GIVEN** 同じ表示範囲を指定した分割の異なる異常マップがある
- **WHEN** 運用者が検査を実行する
- **THEN** 同じ異常マップ値は同じ色、範囲外は端の色になり、スコアと判定は表示範囲によって変わらない

### Requirement: REQ-011 元画像単位の判定集約

システムは、同じ元画像・グループに属する分割判定を集約する時に、一つでも `anomaly` があればそのグループの元画像判定を `anomaly`、全分割が `normal` の場合だけそのグループの元画像判定を `normal`、それ以外はそのグループの元画像判定を `undetermined` と記録しなければならない(MUST)。

#### Scenario: REQ-011-S01 一つの異常を元画像の異常へ集約する

- **GIVEN** 同じ元画像・グループの分割判定に一つ以上の `anomaly` がある
- **WHEN** システムが元画像結果を集約する
- **THEN** システムは他の分割判定にかかわらずそのグループの元画像判定を `anomaly` と記録する

#### Scenario: REQ-011-S02 全分割正常を元画像の正常へ集約する

- **GIVEN** 同じ元画像・グループに必要な全分割が存在し、全ての分割判定が `normal` である
- **WHEN** システムが元画像結果を集約する
- **THEN** システムはそのグループの元画像判定を `normal` と記録する

#### Scenario: REQ-011-S03 判定不能を未判定へ集約する

- **GIVEN** `anomaly` はなく、位置合わせ失敗、分割不足、推論失敗その他の理由による `undetermined` または `error` の分割が一つ以上ある
- **WHEN** システムが元画像結果を集約する
- **THEN** システムはそのグループの元画像判定を `undetermined` と記録する
- **AND** 原則として再撮影が必要であり、別の扱いは評価者判断であることを結果へ記録する

#### Scenario: REQ-011-S04 グループ間の判定を集約しない

- **GIVEN** 同じ元画像を検査した二つのグループで判定が異なる
- **WHEN** 運用者が結果を確認する
- **THEN** グループごとの判定が区別して保存され、グループ間を集約した型番全体の判定は保存されない

### Requirement: REQ-012 元画像単位の検査結果契約

システムは、検査対象の元画像・グループごとに、元画像名、型番、グループID、対象分割ID、使用checkpoint、スコア契約、各分割ID・画像名・異常スコア・判定・結果画像・エラー・使用閾値・閾値の出どころ・表示範囲、グループ内の元画像判定、処理日時、位置合わせ結果、エラー、警告および共通実行記録を機械可読な結果として保存しなければならない(MUST)。<br />
グループ単位の `threshold` と `heatmap_range` は結果に含めない。閾値の出どころは `provisional` または `configured` とする。推論不能な分割にも使用予定の閾値・出どころ・表示範囲を記録し、スコアを `null` とする。スコア源は `supersimplenet.pred_score`、PostProcessorは無効とする。共通実行記録にはコマンド、型番、処理したグループID、開始・終了日時、コマンド単位の処理時間、終了コード、終了状態、デバイス、OS・Python、主要依存関係、警告、エラーを含める。

#### Scenario: REQ-012-S01 追跡可能な JSON 結果を保存する

- **GIVEN** 有効な検査入力と、正常・異常・未判定・一部分割エラーのいずれかを含む元画像がある
- **WHEN** システムが元画像の検査結果を確定する
- **THEN** 各分割の使用閾値、`provisional` または `configured`、表示範囲、判定と、従来どおり集約した元画像判定を含むJSONが保存される
- **AND** 判定不能な分割のスコアは `null` で、グループ直下の旧閾値・表示範囲項目はない

#### Scenario: REQ-012-S02 不正な結果契約を拒否する

- **GIVEN** 分割の閾値・出どころ・表示範囲が欠落または不正、旧グループ単位項目がある、スコア契約・判定・実行記録・日時のいずれかが不正な結果がある
- **WHEN** システムが元画像結果を生成または読み戻す
- **THEN** 不正な項目と理由を示して結果契約を拒否し、正常な検査結果として扱わない

#### Scenario: REQ-012-S03 同じstemの元画像結果を区別して保存する

- **GIVEN** 同じstemで拡張子だけが異なる複数の試験元画像がある
- **WHEN** システムが検査結果を保存する
- **THEN** 拡張子付き元画像名を含む一意なJSON名と分割結果画像名を使い、互いを上書きしない

#### Scenario: REQ-012-S04 不正な試験manifestのパスと対応関係を拒否する

- **GIVEN** 試験manifestの型番、元画像名・分割画像名のパス要素や重複、分割の元画像参照、分割ID、拡張子付き画像名と2桁以上のIDから決まる分割名の不整合、または準備領域・manifest・参照分割画像のシンボリックリンクがある
- **WHEN** 運用者が検査を実行する
- **THEN** 不正な項目と理由を示して推論前に拒否し、管理外のファイルと既存結果を変更しない

#### Scenario: REQ-012-S05 グループの結果を区別する

- **GIVEN** 同じ元画像・分割IDを異なる条件の二つのグループで検査する
- **WHEN** 運用者が全グループの検査を実行する
- **THEN** 各グループの結果は別々に保存され、各分割の使用閾値・出どころ・表示範囲を識別できる

#### Scenario: REQ-012-S06 準備時と異なる試験設定を拒否する

- **GIVEN** 試験準備後に分割位置、画像サイズまたは位置合わせ条件が変わった
- **WHEN** 運用者が検査を実行する
- **THEN** 準備指紋の不一致を推論前に示し、既存結果を保持して `test-pre` の再実行を案内する

### Requirement: REQ-013 明示的な再検査

システムは、運用者が `test` を実行した時に、対象グループの全結果を型番の結果領域内で完成させてから、グループ単位で旧結果を新結果へ置き換えなければならない(MUST)。<br />
公開前の失敗・中断では対象グループの旧結果を保持する。公開時は旧グループ結果を削除してから完成済みの新結果を移す。公開途中の中断で結果が欠けた場合は、運用者が `test` を再実行する。グループ間の新旧混在は全グループの再検査で解消する。

#### Scenario: REQ-013-S01 旧結果だけを置き換える

- **GIVEN** 対象グループの旧結果がある
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** 全対象グループの新結果が完成するまで旧結果を保持し、完成後は各対象グループに最新結果一式だけを残す
- **AND** 結果を固定したグループ別の場所から直接読める

#### Scenario: REQ-013-S02 指定グループだけを再検査する

- **GIVEN** 複数グループの結果がある
- **WHEN** 運用者が `test --model <型番> --group <ID>` を実行する
- **THEN** 指定グループだけを新結果へ置き換え、他グループの結果を変更しない

#### Scenario: REQ-013-S03 公開前の中断で旧結果を保持する

- **GIVEN** 対象グループの旧結果がある
- **WHEN** 全対象グループの新結果が完成する前に失敗または中断する
- **THEN** 対象グループの旧結果をすべて保持し、一時結果を整理して失敗グループIDと理由を表示する
- **AND** 運用者は原因を直して検査を再実行できる

#### Scenario: REQ-013-S04 公開途中の中断を検出する

- **GIVEN** 結果の公開途中で中断し、対象グループの結果が欠けている
- **WHEN** 運用者が次の `test` を実行する
- **THEN** 新たな検査結果を作成して公開する
- **AND** 完了までは欠けた結果を正常な結果として扱わない

#### Scenario: REQ-013-S05 不正な現行結果参照を拒否する

- **GIVEN** 結果フォルダまたは親フォルダがシンボリックリンクである
- **WHEN** 運用者が検査を開始する
- **THEN** システムは不正なパスを示して拒否し、リンク先や管理外のファイルを読み書き・削除しない

#### Scenario: REQ-013-S07 全グループ検査で不正な現行参照を更新する

- **GIVEN** 準備済み試験画像と全グループの学習成果物が有効である
- **WHEN** 運用者が全グループの `test` を実行する
- **THEN** 全対象グループの結果を完成させた後に各グループを公開する
- **AND** 公開途中の中断で新旧が混在していても、全件成功後は設定にある全グループの新結果を読める

#### Scenario: REQ-013-S08 検査以外のコマンドを妨げない

- **GIVEN** 検査結果領域に前回の一時結果が残っている
- **WHEN** 運用者が `train-pre`、`train`、`test-pre` のいずれかを実行する
- **THEN** 検査結果だけを理由に処理を拒否しない
- **AND** 結果領域の管理外ファイルに触れない

#### Scenario: REQ-013-S09 現行グループ以外の結果を整理する

- **GIVEN** 型番設定にないグループ結果が残っている
- **WHEN** 運用者が全グループの `test` を正常に実行する
- **THEN** 設定にあるグループの新結果を公開し、設定にないグループ結果だけを削除する
- **AND** 管理外のファイルは削除しない

#### Scenario: REQ-013-S10 整理の中断後に再試行する

- **GIVEN** 前回の検査で一時結果の整理が途中で止まった
- **WHEN** 運用者が次の `test` を実行する
- **THEN** システムは対象型番の管理対象一時領域を整理してから新しい検査を開始する
- **AND** 整理できない場合は理由を示して停止し、管理対象外を変更しない

#### Scenario: REQ-013-S11 全グループ検査の途中失敗を示す

- **GIVEN** 複数グループの旧結果があり、後続グループの新結果作成中に失敗する
- **WHEN** 運用者が全グループの `test` を実行する
- **THEN** 失敗グループIDと理由を示してエラー終了する
- **AND** 先に作成を終えたグループを含む全対象グループの旧結果を保持する

#### Scenario: REQ-013-S12 残った一時領域を整理する

- **GIVEN** 前回の検査中断で管理対象の一時結果が残っている
- **WHEN** 運用者が次の `test` を実行する
- **THEN** 残った一時結果を削除して新しい結果を作り、公開まで対象グループの旧結果を保持する

### Requirement: NREQ-001 対象環境と実行記録

システムは、Ubuntu 24.04 LTS (ネイティブまたは WSL2) および Apple silicon の macOS で Python 3.13 を使用する場合、学習、推論、結果保存を実行でき、各コマンドの結果、処理時間、警告・エラー、主要依存関係およびデバイス情報を記録できなければならない(MUST)。<br />
利用可能な CUDA GPU がない場合は CPU を使用する。macOS での Apple GPU 利用はこの要件に含めない。

#### Scenario: NREQ-001-S01 対象 OS の実行契約を確認する

- **GIVEN** Ubuntu 24.04 LTS (ネイティブまたは WSL2) または Apple silicon の macOS に固定済み依存関係と有効な小規模試験データが導入されている
- **WHEN** 運用者が分割位置確認から検査までのスモーク試験を実行する
- **THEN** システムは全コマンドの終了状態、処理時間、依存関係の版および使用デバイスを運用記録へ出力する
- **AND** 新しく生成したモデル、画像および JSON を対象環境上で読み戻せる

#### Scenario: NREQ-001-S02 GPU 不能時の復旧可能性を確認する

- **GIVEN** GPU 経路を無効化した対象環境の試験環境がある
- **WHEN** 運用者が学習と検査のスモーク試験を実行する
- **THEN** システムは CPU へ切り替えて完了し、切り替え理由と処理時間を運用記録へ出力する

### Requirement: REQ-016 アプリ生成checkpointの契約照合

システムは、アプリが生成したcheckpointを用いて検査を開始する時に、保存された型番、グループID、スコア契約、暫定閾値および擬似異常の設定値を最良試行と現在の設定に照合しなければならない (MUST)。

#### Scenario: REQ-016-S01 一致するcheckpointで検査する

- **GIVEN** 型番、グループID、スコア契約および暫定閾値が設定と一致するアプリ生成checkpointがある
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** 契約照合を通過し、分割画像の検査が実行される

#### Scenario: REQ-016-S02 メタデータのないcheckpointを拒否する

- **GIVEN** 必要なメタデータを持たないcheckpointがある
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** 必要なメタデータがない理由を示して検査開始前にエラー終了する
- **AND** 運用者は正しい学習成果物を用意して再実行できる

#### Scenario: REQ-016-S03 別グループのcheckpointを拒否する

- **GIVEN** 要求グループと異なるグループIDを持つcheckpointがある
- **WHEN** 運用者がそのグループの検査を実行する
- **THEN** グループ不一致を示して推論前に拒否し、既存の結果を保持する

#### Scenario: REQ-016-S04 新旧の学習成果物を混在させない

- **GIVEN** 新しい最良試行と古いcheckpointを組み合わせた、擬似異常の設定値が一致しない成果物がある
- **WHEN** 運用者が検査を実行する
- **THEN** 不一致を示して推論前に拒否し、`train` からのやり直しを促す

#### Scenario: REQ-016-S05 古い型番設定の閾値を使わない

- **GIVEN** 新しい学習成果物と古い型番設定の暫定閾値が一致しない
- **WHEN** 運用者が検査を実行する
- **THEN** 閾値の不一致を示して推論前に拒否し、`train` からのやり直しを促す

#### Scenario: REQ-016-S06 暫定閾値の未設定を案内する

- **GIVEN** 型番設定の暫定閾値が未設定である
- **WHEN** 運用者が検査を実行する
- **THEN** `train` の実行が必要と案内して推論前に拒否する

### Requirement: REQ-018 検査用閾値の選択と記録

システムは、運用者がグループを検査した時に、各分割の `inspection_threshold` が `null` なら整合確認済みのグループ暫定閾値を、0以上1以下の有限数値ならその指定値を使用し、使用値と出どころを分割結果へ記録しなければならない(MUST)。<br />
暫定閾値は `group_detail`、checkpoint、最良試行で整合を確認する。使用閾値との一致も `anomaly` とする。

#### Scenario: REQ-018-S01 検査用閾値が未指定なら暫定閾値を使用する

新形式では「未指定」をキーの欠落と扱い、暫定閾値を使用するには `null` を明示する。

- **GIVEN** 分割の `inspection_threshold` が欠落している
- **WHEN** 運用者が検査を実行する
- **THEN** グループIDと分割ID、必須項目の欠落を示して入力不備として拒否し、既存結果を保持する

#### Scenario: REQ-018-S02 明示的な null なら暫定閾値を使用する

- **GIVEN** 分割の `inspection_threshold` が `null` である
- **WHEN** 運用者が検査を実行する
- **THEN** グループの暫定閾値で判定し、分割結果に使用値と `provisional` を記録する

#### Scenario: REQ-018-S03 指定した検査用閾値を使用する

- **GIVEN** 分割の指定閾値が暫定閾値と異なる
- **WHEN** 運用者が検査を実行する
- **THEN** 指定値で判定し、分割結果に使用値と `configured` を記録し、暫定閾値を変更しない

#### Scenario: REQ-018-S04 境界値を使用する

- **GIVEN** 分割の指定閾値が0または1である
- **WHEN** 運用者が検査を実行する
- **THEN** その値を使い、スコアが等しければ `anomaly` と記録する

#### Scenario: REQ-018-S05 不正な検査用閾値を拒否する

- **GIVEN** 分割の閾値が範囲外、非有限、数値以外、または真偽値である
- **WHEN** 運用者が型番のいずれかのコマンドを実行する
- **THEN** グループID・分割ID・理由を示して入力不備として拒否し、既存成果物を更新しない

#### Scenario: REQ-018-S06 暫定閾値の不整合を上書き値で隠さない

- **GIVEN** 指定閾値が有効でも、グループ設定・checkpoint・最良試行の暫定閾値が一致しない
- **WHEN** 運用者が検査を実行する
- **THEN** 不一致を示して推論前に拒否し、成果物の確認を促す

### Requirement: REQ-019 型番別ヒートマップ表示範囲の指定

システムは、運用者がグループの検査を実行した時に、各分割に明示した有限数値の `heatmap_range.min < heatmap_range.max` をその分割の可視化に使用しなければならない(MUST)。<br />
異常マップ値を0～1へ制限せず、表示範囲はスコア・閾値・判定を変更しない。

#### Scenario: REQ-019-S01 有効な表示範囲を使用する

- **GIVEN** 同じグループの分割に異なる有効な表示範囲がある
- **WHEN** 運用者が検査を実行する
- **THEN** 各分割の指定範囲で色付けし、分割結果に使用範囲を記録する
- **AND** 表示範囲だけの変更はスコアと判定を変更しない

#### Scenario: REQ-019-S02 未指定または不正な表示範囲を拒否する

- **GIVEN** 分割の表示範囲が欠落、片側だけ、数値以外、真偽値、非有限、または `min >= max` である
- **WHEN** 運用者が型番のいずれかのコマンドを実行する
- **THEN** グループID・分割ID・理由を示して入力不備として拒否し、既存成果物を更新しない

### Requirement: NREQ-002 各 CLI の実行内容の可読性

システムは、運用者が `check`、`train-pre`、`train`、`test-pre`、`test` のいずれかを実行した時に、処理対象、現在の処理段階、終了結果、警告とエラーを人が読める形で表示し、既存の機械可読な終了記録と終了コードを維持しなければならない(MUST)。

#### Scenario: NREQ-002-S01 正常終了を理解できる

- **GIVEN** 有効な入力と対象型番がある
- **WHEN** 運用者がいずれかの CLI を実行する
- **THEN** システムは処理対象と段階、終了状態、処理時間、成果物または処理件数を読める形で表示する
- **AND** 標準出力から従来の1件の実行記録 JSON を読み取れる

#### Scenario: NREQ-002-S02 失敗と警告を理解できる

- **GIVEN** 設定不備、位置合わせ失敗、または処理失敗がある
- **WHEN** 運用者が該当する CLI を実行する
- **THEN** システムは対象、理由、終了状態を読める形で表示し、警告とエラーを区別する
- **AND** 既存の終了コードと機械可読な実行記録を維持する

### Requirement: NREQ-003 検査中の元画像進捗の可読性

システムは、運用者が`test --model <型番>`を実行した時に、試験準備済み元画像の処理済み件数と総件数を一回のコマンドにつき一つの進捗として検査中に標準エラーへ表示し、端末では進捗バー、端末以外では件数表示を用いなければならない(MUST)。

進捗の対象は元画像であり、全対象グループについて一つの元画像の判定集約と結果JSONの保存が終わった時に、その元画像を一件だけ進める。ただし最後の一件は、対象グループの結果一式の公開を終えた時に進める。進捗表示は標準出力の実行記録JSONと終了コードを変更しない。

#### Scenario: NREQ-003-S01 端末で検査の進捗を確認する

- **GIVEN** 複数グループと複数の試験準備済み元画像があり、標準エラーが端末である
- **WHEN** 運用者が`test --model <型番>`を実行する
- **THEN** システムは全対象グループで処理を終えた元画像ごとに処理済み件数と元画像総数を示す一つの進捗バーを更新する
- **AND** 正常終了時に総件数まで到達し、標準出力には従来の実行記録JSONを一件だけ出す

#### Scenario: NREQ-003-S02 端末以外で検査の進捗を確認する

- **GIVEN** 複数グループと複数の試験準備済み元画像があり、標準エラーが端末ではない
- **WHEN** 運用者が`test --model <型番>`を実行する
- **THEN** システムは開始時の`0/元画像総数`から全対象グループで各元画像の処理を終えた時まで、一つの件数表示を標準エラーへ出す
- **AND** 標準出力には従来の実行記録JSONを一件だけ出す

#### Scenario: NREQ-003-S03 未判定や分割エラーを処理済みとして数える

- **GIVEN** 試験元画像の一部に位置合わせ失敗、分割不足、または個別の推論エラーがある
- **WHEN** 運用者が`test --model <型番>`を実行する
- **THEN** システムは全対象グループの元画像単位の結果を確定したものだけ、一元画像につき一度だけ処理済み件数へ加える
- **AND** 警告・エラー・判定結果と終了コードは従来の契約を維持する

#### Scenario: NREQ-003-S04 処理全体の失敗を完了と表示しない

- **GIVEN** 検査の途中で処理全体が失敗する
- **WHEN** 運用者が`test --model <型番>`を実行する
- **THEN** システムは全対象グループで結果を確定した元画像数を超えて進捗を増やさず、最終書込みまたは結果公開に失敗した場合も総件数への到達を表示せず、失敗理由と終了状態を表示する
- **AND** 運用者は原因を修正して再実行できる

### Requirement: REQ-023 検査対象グループの選択と事前照合

システムは、運用者が `test --model <型番>` を実行した時に全グループを、`--group <ID>` を指定した時にそのグループだけを検査し、各対象グループの学習成果物を、そのグループの推論前に照合しなければならない(MUST)。

#### Scenario: REQ-023-S01 全グループを検査する

- **GIVEN** 全グループの整合した学習成果物と全分割の試験準備結果がある
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** 元画像ごとに全グループの検査結果が保存される

#### Scenario: REQ-023-S02 指定グループだけを検査する

- **GIVEN** 指定グループの学習成果物と全分割の試験準備結果があり、他グループの結果も存在する
- **WHEN** 運用者が `test --model <型番> --group <ID>` を実行する
- **THEN** 指定グループの結果だけが更新され、他グループの結果は保持される

#### Scenario: REQ-023-S03 不足モデルを対象グループの推論前に通知する

- **GIVEN** 対象グループの一つ以上でcheckpointまたは最良試行結果が欠けている
- **WHEN** 運用者が検査を実行する
- **THEN** 不足するグループIDと成果物を示して入力不備として終了する
- **AND** 全対象グループの旧結果を保持し、学習成果物を整えて再実行できる

#### Scenario: REQ-023-S04 未定義グループを拒否する

- **GIVEN** 設定に存在しないグループIDが指定される
- **WHEN** 運用者が検査を実行する
- **THEN** 利用可能なグループIDを示して入力不備として終了し、既存結果を保持する

#### Scenario: REQ-023-S05 全グループの検査途中失敗で完了分を保持する

- **GIVEN** 複数グループの既存検査結果があり、全グループの結果作成中に後続グループで処理全体の失敗が起こる
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** コマンドは失敗グループIDと理由を示してエラー終了する
- **AND** 先に作成を終えたグループを含む全対象グループの旧結果を保持する

### Requirement: REQ-028 グループ別検査結果の名前をID順にそろえる

システムは、運用者がグループの検査を実行した時に、グループIDを最低2桁の0埋めで表した `data/06_result/<model>/group_<ID>/` に最新結果を保存しなければならない(MUST)。<br />
各グループの直下には `<元画像名>.json` と `<分割画像名>_result.png` だけを置く。検査結果のグループIDは整数のままとし、検査完了時は `data/06_result/<model>/` を表示する。

#### Scenario: REQ-028-S01 新形式の結果を保存して読み戻す

- **GIVEN** グループIDが0、9、10、100の有効な学習成果物と試験準備がある
- **WHEN** 運用者が検査を実行する
- **THEN** 各グループの結果は `group_00`、`group_09`、`group_10`、`group_100` の直下に元画像別JSONと分割結果画像だけを持つ
- **AND** 結果JSONのグループIDは整数であり、検査完了表示は型番の結果ルートを示す

#### Scenario: REQ-028-S02 同じ名前の旧結果を残さない

- **GIVEN** 対象グループの旧結果に、今回の検査対象から外れた元画像のファイルがある
- **WHEN** 運用者が検査を再実行する
- **THEN** 対象グループの保存先には今回作成したJSONと画像だけが残る

### Requirement: REQ-036 検査開始時の分割別閾値表示

システムは、運用者が検査を開始した時に、各対象グループ・分割IDについて使用閾値と `provisional` または `configured` の出どころを表示しなければならない(MUST)。

#### Scenario: REQ-036-S01 分割ごとの使用値を確認する

- **GIVEN** 一つのグループに暫定閾値を使う分割と設定閾値を使う分割がある
- **WHEN** 運用者が検査を開始する
- **THEN** グループID・分割IDごとに使用値と出どころが表示され、結果JSONの値と一致する

### Requirement: REQ-041 グループ別試験準備の照合

システムは、運用者が検査を実行した時に、各対象グループの試験準備をそのグループの設定と照合してから使用しなければならない(MUST)。

#### Scenario: REQ-041-S01 指定グループの準備を使用する

- **GIVEN** 複数グループの準備がある
- **WHEN** 運用者が `test --model <型番> --group <ID>` を実行する
- **THEN** 指定グループの分割と未判定情報だけが検査され、他グループの準備と結果は変更されない

#### Scenario: REQ-041-S02 全グループの準備を使用する

- **GIVEN** 全グループの準備がある
- **WHEN** 運用者が `test --model <型番>` を実行する
- **THEN** 各グループで対応する試験準備を照合して検査できる

#### Scenario: REQ-041-S03 準備欠落・不整合を拒否する

- **GIVEN** 対象グループの準備が欠落するか設定と一致しない
- **WHEN** 運用者が検査を実行する
- **THEN** 対象グループと再準備の必要性を示して推論前に拒否し、旧結果を保持する
