# 画像準備仕様

## Purpose

運用者が型番ごとの基準画像、位置合わせ条件、分割範囲およびブラックリストを管理し、大容量の元画像から学習・検査に利用できる追跡可能な分割画像を再現可能に準備する能力を提供する。

## Requirements

### Requirement: REQ-001 型番設定と分割範囲の確認

システムは、運用者が型番を指定して分割位置確認を要求した時に、型番設定の基準画像へ全分割範囲と分割 ID を重ねた確認画像、および各グループの対象範囲とグループ ID・分割 ID を区別できる確認画像を保存しなければならない(MUST)。

座標は左上原点、右方向を x、下方向を y とするピクセル単位とし、分割範囲は左上を含み右端・下端を含まない正方形とする。
`setting.ini` の `[IMAGE]` セクションにある `SIZE` は、値と同じ行にコメントを含めず、値全体を正の10進整数として扱う。
`RESIZE` は縦横に適用する0より大きく1以下の倍率とし、未指定時は1とする。<br />
型番設定の `range.x`・`range.y` は縮小前の基準画像の座標とする。<br />
確認画像では指定倍率で座標を換算し、縮小後の基準画像上に切り出し位置を表示する。<br />
換算後の座標は、縮小前座標に `RESIZE` を掛け、小数部が0.5以上なら切り上げる整数とする。<br />
分割範囲の一辺は縮小後も `SIZE` ピクセルとする。
型番設定の基準画像 `base` はディレクトリを含まないファイル名だけを許可し、`data/01_original_train/<型番>/` 配下のファイルとして解決しなければならない(MUST)。絶対パス、`.`、`..`、パス区切り文字を含む値、または解決後に既知ルート外となる値を処理開始前に拒否しなければならない(MUST)。

#### Scenario: REQ-001-S01 有効な設定から確認画像を生成する

- **GIVEN** 型番の基準画像、正の整数である画像サイズ、有効な縮小倍率、一意な分割 ID、および縮小前の基準画像で指定し、換算後に縮小後の画像内に収まる左上座標が設定されている
- **WHEN** 運用者が `check --model <型番>` を実行する
- **THEN** システムは縮小前座標を換算した縮小後の基準画像上に各分割範囲の矩形と ID を描いた型番別の全範囲確認画像とグループ別確認画像を保存する
- **AND** 処理結果、出力先および処理時間を運用者へ表示する

#### Scenario: REQ-001-S02 無効な分割範囲を拒否する

- **GIVEN** 換算後の分割範囲が縮小後の基準画像外にはみ出す、分割 ID が重複する、画像サイズが整数でないか正でない、縮小倍率が0以下・1超・非数値の設定がある、または有効な倍率でも基準画像の縮小後の縦横いずれかが0ピクセルとなる
- **WHEN** 運用者が `check --model <型番>` を実行する
- **THEN** システムは対象の設定項目または画像と理由を示して処理をエラー終了する。縮小不能な画像は処理失敗、設定と範囲の不備は入力不備として扱う
- **AND** 不完全な確認画像を正常結果として保存しない

#### Scenario: REQ-001-S03 基準画像のルート外参照を拒否する

- **GIVEN** 型番設定の `base` に絶対パス、`.`、`..`、パス区切り文字を含む値、または学習元画像の型番別ルート外へ解決される値が指定されている
- **WHEN** 運用者が当該型番のコマンドを実行する
- **THEN** システムは `base` が安全なファイル名ではないことを示して処理開始前にエラー終了する
- **AND** 既知ルート外のファイルを読み書きしない

#### Scenario: REQ-001-S04 縮小前の指定位置を確認する

- **GIVEN** `RESIZE = 0.5`、`SIZE = 500`、縮小前基準画像で `x = 400` と `x = 401` の異なる分割 ID がある
- **WHEN** 運用者が `check --model <型番>` を実行する
- **THEN** システムは縮小後画像の `x = 200` と `x = 201` からそれぞれ500ピクセル四方の範囲を描き、指定した分割 ID を表示する

#### Scenario: REQ-001-S05 重複所属を確認する

- **GIVEN** 同じ分割IDを含む二つのグループがある
- **WHEN** 運用者が `check --model <型番>` を実行する
- **THEN** 全範囲画像と両グループの確認画像に同じ分割位置とIDが表示される
- **AND** 各グループの対象範囲を区別できる

### Requirement: REQ-002 学習画像の位置合わせ・分割・除外

システムは、運用者が学習準備を要求した時に、型番の各学習元画像を基準画像へ位置合わせし、ブラックリスト対象を除外して、指定グループまたは全グループについて、元画像名と2桁ゼロ埋めの分割 ID で対応付く分割画像とグループ別の準備記録を保存しなければならない(MUST)。

ORB位置合わせは、ホモグラフィ推定前の対応点数が設定された最低マッチ数以上であり、設定されたRANSAC再投影誤差とRANSAC信頼確率でホモグラフィを推定でき、返却マスクから算出したインライア比率が設定された最低値以上である場合だけ成功としなければならない(MUST)。<br />
対応点は各特徴点の近傍2候補の距離を比較し、最良候補の距離が次点候補の距離に比率閾値を掛けた値より小さい場合だけ採用する。<br />
`knn_k` は2、`ratio_threshold` は0より大きく1より小さい値とする。<br />
初期値は `knn_k` 2、`ratio_threshold` 0.75、最低マッチ数10、RANSAC再投影誤差8.0px、RANSAC信頼確率0.95、最低インライア比率0.2としなければならない(MUST)。<br />
対象グループの成果物は完成まで旧成果物を変更せず、完成したグループから置き換える。公開前の失敗・中断では旧成果物を維持し、次回実行時に残った一時領域を削除する。公開途中の中断による欠落は学習の利用前に拒否し、準備のやり直しを案内する。

#### Scenario: REQ-002-S01 学習用分割画像を生成する

- **GIVEN** 有効な型番設定と、縮小後に設定した対応点条件で位置合わせ可能な学習元画像がある
- **WHEN** 運用者が `train-pre --model <型番>` を実行する
- **THEN** システムは基準画像と元画像を指定倍率で縮小して位置合わせし、縮小前座標を換算した開始位置から `SIZE` ピクセル四方の全グループで使う分割範囲を切り出し、`<元画像名>_<2桁分割ID>.<元拡張子>` の名称で対応するグループの学習領域へ保存する
- **AND** 元画像は変更しない

#### Scenario: REQ-002-S02 ブラックリスト対象を除外する

- **GIVEN** 学習元画像名と分割 ID の組み合わせが型番のブラックリストに指定されている
- **WHEN** 運用者が学習準備を実行する
- **THEN** システムは該当する分割画像を学習領域へ保存しない
- **AND** 除外した元画像名と分割 ID を処理結果へ記録する

#### Scenario: REQ-002-S03 位置合わせに失敗した学習画像を除外する

- **GIVEN** 学習元画像が最低マッチ数、ホモグラフィ推定、または最低インライア比率のいずれかを満たさず、基準画像へ位置合わせできない
- **WHEN** 運用者が学習準備を実行する
- **THEN** システムは該当する元画像の全分割を学習対象から除外する
- **AND** 元画像名、失敗理由および再確認が必要であることを警告として表示する

#### Scenario: REQ-002-S04 分割範囲外をエラーにする

- **GIVEN** 位置合わせ後の学習画像に対して分割範囲が画像外にはみ出す
- **WHEN** 運用者が学習準備を実行する
- **THEN** システムは元画像名と分割 ID を示して処理をエラー終了する
- **AND** 公開前なら既存の対象グループ成果物を変更しない

#### Scenario: REQ-002-S05 読込み不能な学習画像で既存成果物を維持する

- **GIVEN** 型番の学習元画像を画像として読み込めない
- **WHEN** 運用者が学習準備を実行する
- **THEN** システムは対象の元画像名を示して処理失敗としてエラー終了する
- **AND** 公開前なら既存の対象グループ準備成果物を維持する

#### Scenario: REQ-002-S06 対応点判定設定の不備を拒否する

- **GIVEN** `knn_k` が2でない、または `ratio_threshold` が0以下・1以上・非数値である
- **WHEN** 運用者が学習準備を実行する
- **THEN** システムは不正な設定項目を示して処理開始前にエラー終了する
- **AND** 元画像と既存の準備成果物を維持する

#### Scenario: REQ-002-S07 指定グループだけを準備する

- **GIVEN** 複数グループと既存の別グループの準備結果がある
- **WHEN** 運用者が `train-pre --model <型番> --group <ID>` を実行する
- **THEN** 指定グループの分割だけを準備してそのグループの記録を更新する
- **AND** 別グループの準備結果を保持する

#### Scenario: REQ-002-S08 全グループを一度の実行で準備する

- **GIVEN** 複数グループで同じ分割を参照する有効な設定がある
- **WHEN** 運用者が `train-pre --model <型番>` を実行する
- **THEN** 各グループの対象分割と準備記録が完成したグループから順に公開される
- **AND** 同じ元画像に対するグループ間の位置合わせ結果が一致する

#### Scenario: REQ-002-S09 残った一時領域を整理する

- **GIVEN** 前回の中断で学習準備の一時領域が残り、正式領域には旧成果物がある
- **WHEN** 運用者が次の学習準備を実行する
- **THEN** 残った一時領域を削除して新たに準備し、公開まで旧成果物を変更しない

#### Scenario: REQ-002-S10 公開途中の欠落を拒否する

- **GIVEN** 学習準備成果物の削除と公開の間で中断し、対象グループの成果物が欠けている
- **WHEN** 運用者がそのグループの学習を実行する
- **THEN** 準備成果物の欠落を示して拒否し、`train-pre` のやり直しを促す

### Requirement: REQ-003 試験画像の位置合わせと分割

システムは、運用者が試験準備を要求した時に、ブラックリストを適用せず、型番の各試験元画像を基準画像へ位置合わせして、元画像名と2桁ゼロ埋めの分割 ID で対応付く分割画像または未判定引き継ぎ情報を生成しなければならない(MUST)。<br />
試験画像にも学習画像と同じORB位置合わせ成功条件を適用しなければならない(MUST)。<br />
試験準備の完成までは旧成果物を変更せず、公開前の失敗・中断では旧成果物を維持する。次回実行時に残った一時領域を削除する。

#### Scenario: REQ-003-S01 試験用分割画像を生成する

- **GIVEN** 有効な型番設定と、縮小後に設定した対応点条件で位置合わせ可能な試験元画像がある
- **WHEN** 運用者が `test-pre --model <型番>` を実行する
- **THEN** 全分割を切り出して型番別試験領域へ保存し、元画像は変更しない
- **AND** 学習用ブラックリストに一致する画像であっても試験対象から除外しない

#### Scenario: REQ-003-S02 位置合わせ失敗を検査へ引き継ぐ

- **GIVEN** 試験元画像が対応点条件を満たさず位置合わせできない
- **WHEN** 運用者が試験準備を実行する
- **THEN** 該当元画像を正常な分割画像一式として保存せず、失敗理由と `recapture_required=true` を保存して警告する

#### Scenario: REQ-003-S03 試験分割範囲外をエラーにする

- **GIVEN** 位置合わせ後の試験画像に対して分割範囲が画像外にはみ出す
- **WHEN** 運用者が試験準備を実行する
- **THEN** 元画像名と分割 ID を示してエラー終了し、公開前なら旧試験準備成果物を維持する

#### Scenario: REQ-003-S04 読込み不能な試験画像で既存成果物を維持する

- **GIVEN** 型番の試験元画像を画像として読み込めない
- **WHEN** 運用者が試験準備を実行する
- **THEN** 対象の元画像名を示してエラー終了し、公開前なら旧試験準備成果物を維持する

#### Scenario: REQ-003-S05 次回実行で一時領域を整理する

- **GIVEN** 前回の中断で試験準備の一時領域が残っている
- **WHEN** 運用者が `test-pre` を再実行する
- **THEN** 残った一時領域を削除して最初から準備し、完成まで旧成果物を保持する

### Requirement: REQ-017 学習・試験準備の進捗確認

システムは、運用者が `train-pre` または `test-pre` を実行した時に、対象元画像の総数と処理済み数を実行中に表示しなければならない(MUST)。

#### Scenario: REQ-017-S01 対象画像の進捗を表示する

- **GIVEN** 複数の学習または試験元画像がある
- **WHEN** 運用者が `train-pre` または `test-pre` を実行する
- **THEN** システムは対象画像数と処理済み数を進行に合わせて表示し、終了時には処理結果を示す

#### Scenario: REQ-017-S02 失敗時の進捗を終了状態と区別する

- **GIVEN** 準備途中に読み込み不能な元画像がある
- **WHEN** 運用者が `train-pre` または `test-pre` を実行する
- **THEN** システムは失敗した画像と理由、完了していない状態を示し、処理済み件数を成功件数として表示しない

### Requirement: REQ-021 必須グループの設定確認

システムは、運用者が型番のいずれかのコマンドを実行した時に、すべてのグループの `ranges` と各分割条件を検証し、不備があれば成果物の更新前に入力不備として拒否しなければならない(MUST)。<br />
`groups` は非空で、各グループの `id` は0以上の一意な整数とする。各グループの `ranges` は必須の非空配列であり、各要素に `id`、`inspection_threshold`、`heatmap_range` を必須とする。`id` は共通 `range` にある分割IDで、同じグループ内で重複させない。同じIDを複数グループで使用してよい。`inspection_threshold` は明示した `null` または0以上1以下の有限数値とし、`heatmap_range` は有限数値の `min` と `max` を持ち、`min < max` とする。数値に真偽値を含めない。<br />
廃止された項目である `range_ids`、グループ直下の `inspection_threshold` と `heatmap_range` は、項目名と「廃止された項目」を示して拒否する。欠落、空、型・境界値違反、重複、未定義ID、旧項目は、グループID、判明している場合は分割ID、理由を示す。分割IDが欠落する場合はそのことと要素位置を示す。<br />
基準画像、分割範囲、位置合わせ条件、ブラックリストは型番共通とする。`group_detail` はグループIDの通常の10進文字列をキーとし、各値に `optuna_settings`、`score`、`augmentation` を置く。`groups` のIDと `group_detail` のキーは一対一に対応し、詳細項目を `groups` に置かない。

#### Scenario: REQ-021-S01 全範囲と個別範囲を併存させる

- **GIVEN** 全分割を参照するグループと単一分割を参照するグループに、それぞれ完全な分割条件と詳細設定がある
- **WHEN** 運用者が型番のコマンドを実行する
- **THEN** 両グループが有効として扱われ、同じ分割IDにグループごとに異なる検査値を指定できる

#### Scenario: REQ-021-S02 不正なグループを拒否する

- **GIVEN** グループIDの重複・不正、`ranges` の欠落・空、分割IDの欠落・重複・未定義、閾値または表示範囲の欠落・型・値・順序違反のいずれかがある
- **WHEN** 運用者が `check`、`train-pre`、`train`、`test-pre`、`test` のいずれかを実行する
- **THEN** システムは対象グループID、判明している分割IDまたは要素位置、理由を示して入力不備として終了する
- **AND** 既存の準備・学習・検査成果物と型番設定を更新せず、運用者は修正後に再実行できる

#### Scenario: REQ-021-S03 必須グループの欠落を拒否する

- **GIVEN** 型番設定に `groups` がない
- **WHEN** 運用者が型番のコマンドを実行する
- **THEN** 必須グループがない理由を示して入力不備として終了し、暗黙のグループを作成しない

#### Scenario: REQ-021-S04 詳細設定のID対応を検証する

- **GIVEN** `group_detail` が欠落、余分なIDを持つ、または `"00"` 等の非標準表記を使う
- **WHEN** 運用者が型番のコマンドを実行する
- **THEN** 不一致を示して入力不備として終了し、既存成果物を更新しない

#### Scenario: REQ-021-S05 groups に置けない項目を拒否する

- **GIVEN** `groups` に `optuna_settings`、`score`、`augmentation`、旧 `range_ids`、グループ単位の `inspection_threshold` または `heatmap_range` がある
- **WHEN** 運用者が型番のコマンドを実行する
- **THEN** グループID、項目名と、旧項目については「廃止された項目」を示して入力不備として終了し、既存成果物を更新しない
- **AND** 運用者は詳細項目を `group_detail`、分割条件を `groups[].ranges[]` に置いて再実行できる

### Requirement: REQ-025 準備結果と設定の対応記録

システムは、運用者が学習または試験の画像準備を実行した時に、分割結果へ影響する設定から作った準備指紋をmanifestへ記録しなければならない(MUST)。<br />
学習準備の指紋には型番共通の分割・位置合わせ条件、ブラックリストと対象グループの `ranges[].id` から導いた分割IDを含める。試験準備の指紋にはブラックリストとグループの学習・検査条件を含めない。いずれの指紋にも `inspection_threshold` と `heatmap_range` を含めない。学習manifestの内部 `range_ids` は対象グループの `ranges[].id` を記録する。両方の指紋は輝度補正の有効・無効を区別し、有効な場合は全項目を既定値を適用した値で含める。

#### Scenario: REQ-025-S01 学習準備の条件を記録する

- **GIVEN** 共通分割範囲、位置合わせ条件、ブラックリストと対象グループの分割条件が設定されている
- **WHEN** 運用者が `train-pre --model <型番> --group <ID>` を実行する
- **THEN** 対象グループの学習manifestに、分割IDの内部記録と準備条件の指紋が記録される

#### Scenario: REQ-025-S02 試験準備の条件を記録する

- **GIVEN** 共通分割範囲と位置合わせ条件が設定されている
- **WHEN** 運用者が `test-pre --model <型番>` を実行する
- **THEN** 全分割の試験manifestに準備条件の指紋が記録される
- **AND** ブラックリストやグループの学習・検査条件だけを変更しても試験準備の指紋は変わらない

#### Scenario: REQ-025-S03 有効な輝度補正条件の変更を区別する

- **GIVEN** 輝度補正が有効な学習・試験準備結果がある
- **WHEN** 運用者が有効な輝度補正条件を変更して準備結果を照合する
- **THEN** 条件が異なる準備指紋として扱われ、旧準備結果は使用されない

#### Scenario: REQ-025-S04 検査値だけを変更して再検査する

- **GIVEN** 新形式で作った準備・学習成果物がある
- **WHEN** 運用者が `groups[].ranges[]` の `inspection_threshold` または `heatmap_range` だけを変更して `test` を再実行する
- **THEN** 準備指紋は変わらず、準備・学習を再実行せず変更後の検査値で結果を更新できる

### Requirement: REQ-026 グループ別準備成果物の名前をID順にそろえる

システムは、運用者がグループ別の確認または学習準備を実行した時に、グループIDを最低2桁の0埋めで表した名前でグループ別成果物を保存しなければならない(MUST)。
設定、CLI指定、準備記録のID値は整数のままとする。

#### Scenario: REQ-026-S01 1桁と2桁以上のIDを保存する

- **GIVEN** グループIDが0、9、10、100である
- **WHEN** 運用者が確認と学習準備を実行する
- **THEN** グループ別確認画像と学習準備領域には `group_00`、`group_09`、`group_10`、`group_100` に対応する名前を使用する
- **AND** 設定と準備記録のIDは整数のままである

### Requirement: REQ-027 型番共通の輝度補正条件を検証する

システムは、運用者が型番設定を使用した時に、トップレベルの `brightness_normalization` を型番共通の条件として読み、省略項目には既定値を適用し、不正な値は処理開始前に入力不備として拒否しなければならない(MUST)。<br />
`enabled` は真偽値で既定値 `true`、`statistic` は `median` または `mean` で既定値 `median` とする。<br />
`exclude_above` は1以上255以下の整数で既定値230、`exclude_below` は0以上254以下の整数で既定値0とし、`exclude_below < exclude_above` を要求する。<br />
`min_gain` と `max_gain` は正の有限数で、既定値をそれぞれ0.5と2.0とし、`min_gain <= max_gain` を要求する。<br />
`brightness_normalization` 全体を省略した場合は補正を無効にする。項目を記述した場合だけ、省略した子項目の既定値を適用する。

#### Scenario: REQ-027-S01 省略した補正条件に既定値を適用する

- **GIVEN** `brightness_normalization` を記述し、その一部の子項目を省略した有効な型番設定がある
- **WHEN** 運用者が当該型番の `train-pre` または `test-pre` を実行する
- **THEN** 子項目には既定値が適用され、補正が有効な準備結果を取得できる

#### Scenario: REQ-027-S03 設定全体の省略で補正しない

- **GIVEN** 型番設定に `brightness_normalization` がない
- **WHEN** 運用者が `train-pre` または `test-pre` を実行する
- **THEN** 分割画像は輝度補正を受けず、準備指紋も無効状態を示す

#### Scenario: REQ-027-S02 不正な補正条件を拒否する

- **GIVEN** 補正条件に不正な型・列挙値・範囲外の値・非有限数、`exclude_below >= exclude_above`、または `min_gain > max_gain` がある
- **WHEN** 運用者が当該型番のコマンドを実行する
- **THEN** 不正な項目を示す入力不備として処理開始前に終了し、元画像と既存の準備成果物を変更しない
- **AND** 運用者は設定を修正して再実行できる

### Requirement: REQ-028 分割画像の輝度を基準画像に合わせる

システムは、輝度補正が有効な型番について運用者が `train-pre` または `test-pre` を実行した時に、各分割画像を同じ分割範囲の縮小済み基準画像の輝度へ、指定した倍率範囲内で補正して保存しなければならない(MUST)。<br />
輝度値はBGR画像をグレースケールに変換し、`exclude_below` 以上かつ `exclude_above` 未満の画素だけの指定統計量 (`median` または `mean`) とする。該当画素がなければ「値なし」とする。<br />
分割画像の輝度値が正で、両画像の輝度値がある場合、倍率は「基準画像の輝度値 ÷ 分割画像の輝度値」を `min_gain` 以上 `max_gain` 以下へ収めた値とする。分割画像の全BGRチャンネルへ倍率を掛け、0.5以上の小数部を切り上げて整数にし、0以上255以下へ収める。<br />
基準画像または分割画像の輝度値が「値なし」、または分割画像の輝度値が0以下の場合は、その分割画像を補正せずに保存する。`enabled=false` の場合も補正せずに保存する。元画像、基準画像、`check` の確認画像は変更しない。

#### Scenario: REQ-028-S01 学習と試験の分割画像を補正する

- **GIVEN** 補正が有効で、基準画像と対象分割画像に集計可能な画素があり、対象の輝度値が正である
- **WHEN** 運用者が `train-pre` と `test-pre` を実行する
- **THEN** 両準備の各分割画像は、縮小済み基準画像の同じ分割範囲から得た目標値と指定統計量・除外範囲・倍率上下限による補正後の画素値で保存される
- **AND** 元画像と基準画像は変更されない

#### Scenario: REQ-028-S02 倍率と画素値の境界を守る

- **GIVEN** 輝度比が倍率の下限未満または上限超である分割画像と、倍率適用後に整数境界または255を超える画素がある
- **WHEN** 運用者が `train-pre` または `test-pre` を実行する
- **THEN** 保存した分割画像の倍率は指定範囲内に収まり、全チャンネルの値は四捨五入後に0以上255以下となる

#### Scenario: REQ-028-S03 補正できない分割画像を保持する

- **GIVEN** 基準側または対象側に集計可能な画素がない、または対象側の輝度値が0以下である
- **WHEN** 運用者が `train-pre` または `test-pre` を実行する
- **THEN** 該当分割画像は輝度補正を受けずに保存され、他の有効な分割の準備を妨げない

#### Scenario: REQ-028-S04 無効化した補正を適用しない

- **GIVEN** 型番設定に `brightness_normalization.enabled=false` がある
- **WHEN** 運用者が `train-pre` または `test-pre` を実行する
- **THEN** 分割画像は輝度補正を受けずに保存される

### Requirement: REQ-037 型番の残存一時領域を開始時に整理する

システムは、運用者が5コマンドのいずれかを開始した時に、対象型番の前回残った管理対象一時領域を、グループを問わず削除しなければならない(MUST)。管理対象外、別型番、シンボリックリンク先は削除しない。

#### Scenario: REQ-037-S01 他グループの残存物も整理する

- **GIVEN** 対象型番の複数グループと複数工程に前回の一時領域が残る
- **WHEN** 運用者がその型番のいずれかのコマンドを開始する
- **THEN** 対象型番の管理対象一時領域がすべて消え、別型番と管理対象外は残る

#### Scenario: REQ-037-S02 不正な一時領域を拒否する

- **GIVEN** 管理対象一時領域の候補がシンボリックリンクまたは想定外の種類である
- **WHEN** 運用者がその型番のコマンドを開始する
- **THEN** 対象パスを示して拒否し、リンク先と管理対象外を変更しない
